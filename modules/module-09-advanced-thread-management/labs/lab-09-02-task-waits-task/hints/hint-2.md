# Подсказка 2 — механизм, без кода

`std::async` при вызове `get()` может выполнить отложенную задачу в том же
потоке — «задача ждёт задачу» не возникает, потому что ожидающий поток сам
превращается в исполнителя.

Пул с фиксированным числом потоков так не умеет: рабочий поток не может стать
исполнителем задачи из очереди, пока сам заблокирован в `get()`.

Решение из лекции — не ждать впустую. Вместо блокирующего `.get()`:

```text
while (f.wait_for(std::chrono::seconds(0)) != std::future_status::ready) {
    pool.run_pending_task();
}
```

`run_pending_task()` выполняет одну задачу из очереди (или уступает процессор).
Ожидающий поток «помогает» пулу: задачи из очереди выполняются, и рано или
поздно нужный результат появляется. Разблокировки не происходит — ожидание
заменяется полезной работой.
