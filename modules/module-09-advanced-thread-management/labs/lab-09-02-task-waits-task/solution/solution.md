# Решение лабы 9.2

## Предсказание

Программа напечатает **«DEADLOCK: задача ждёт задачу, а рабочий поток занят»**.
Единственный рабочий поток выполняет `worker(0, N)`: отправляет правую
половину в очередь, сам рекурсивно обрабатывает левую. Дойдя до `.get()`, он
блокируется в ожидании результата правой половины. Задачи в очереди никто не
берёт — рабочий поток один, и он занят ожиданием. Ожидание никогда не
завершится: это взаимная блокировка.

Важное следствие: деструктор пула тоже не сможет завершиться. `join_threads`
будет ждать рабочий поток, а тот заблокирован в `get()` навсегда. Поэтому
стартовая программа выходит через `std::_Exit(0)`, не разрушая пул, — иначе
завис бы и сам `main`. Deadlock в пуле — это не только «задача не выполняется»,
это ещё и невозможность аккуратно завершить пул.

## Механизм

Пул с фиксированным числом потоков не может создать исполнителя «из воздуха».
Если все рабочие потоки находятся в `.get()`, задачи из очереди остаются
невыполненными, а их результаты — недоступными. Получается классический
deadlock: каждый ожидает результата задачи, которую некому выполнить. Чем
больше потоков, тем больше вложенных ожиданий нужно для блокировки, но суть
та же: число одновременных ожиданий равно числу потоков, и достаточно N
вложенных задач, чтобы исчерпать пул.

## Почему `std::async` не страдает

Библиотека сама решает, как выполнить асинхронную задачу: в новом потоке или
синхронно при вызове `get()`. Когда свободных потоков нет, отложенная задача
просто выполняется в том потоке, который вызвал `get()`, — «ожидающий поток
сам становится исполнителем». Проблема «задача ждёт задачу» не возникает
принципиально.

## Исправление

Нужно, чтобы ожидающий поток вместо пустого ожидания выполнял задачи из
очереди. Добавляем в пул `run_pending_task()`:

```cpp
void run_pending_task() {
    function_wrapper task;
    if (work_queue.try_pop(task)) {
        task();
    } else {
        std::this_thread::yield();
    }
}
```

А ожидание результата превращается в цикл «проверь готовность — выполни
задачу»:

```cpp
while (f.wait_for(std::chrono::seconds(0)) != std::future_status::ready) {
    pool.run_pending_task();
}
```

`wait_for(0)` мгновенно проверяет готовность, не блокируя. Пока результат не
готов, поток «помогает» пулу: берёт задачу из очереди и выполняет её. Рано или
поздно он дойдёт и до задачи, результат которой ждёт, — та завершится, и
ожидание закончится. Пустое ожидание заменяется полезной работой.

## Проверка

Исправленная программа печатает `sum = 549755289600` (сумма 0..N-1 для
N = 2^20), `result = OK`, exit 0. TSan чист: очередь защищена мьютексом,
данные — `long long` внутри задач, гонок нет.
