# Грабли лабы 9.3

## Оставил `bool` вместо `std::atomic<bool>`

Флаг, который один поток пишет, а другие читают, без атомарности — гонка за
данные (UB). Проверяется только TSan, не «вроде работает».

## Проверял гонку через `thread_local`

ThreadSanitizer не инструментирует доступ через thread-local storage (обращение
идёт через специальный регистр), поэтому гонку за TLS-флаг он НЕ увидит. Для
проверки лабы флаг должен лежать в обычной памяти. Если в решении ты вернул
thread_local-схему из лекции — TSan будет «чист», хотя гонка никуда не делась.

## Одна-единственная запись флага

TSan может не зафиксировать гонку, если неатомарная запись была всего одна и
успела «выпасть» из окна отслеживания. Надёжнее повторные записи (сигнал
подаётся, пока все потоки не подтвердят остановку).

## Забыл перехват `thread_interrupted`

`interruption_point()` бросает исключение в фоновом потоке. Если его не
перехватить — `std::terminate`, программа упадёт. Перехват обязателен.

## Считал, что флаг можно сделать `volatile`

`volatile` не делает операции атомарными и не устраняет гонку за данные.
Только `std::atomic` (или мьютекс) решает проблему.

## Не проверил, что все потоки остановились

После `interrupt()` нужно `join()` каждого потока — это и есть проверка, что
поток реально вышел из цикла по прерыванию. Забыл join — программа может
завершиться с «живым» потоком (UB при завершении процесса).

## Прерывал потоки сразу, не дав им поработать

Если прервать сразу, потоки успеют сделать пару итераций — гонка может не
проявиться. Нужно дождаться накопленной работы (порог), чтобы чтения флага
шли, пока `main` пишет.
