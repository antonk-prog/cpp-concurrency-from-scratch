# Решение лабы 9.3

## Ошибка

В `interrupt_flag` поле `flag` — обычный `bool`. Прерывающий поток вызывает
`set()` (пишет `flag = true`), а прерываемые фоновые потоки в цикле читают
`is_set()`. Одновременные чтение и запись неатомарной переменной из разных
потоков без синхронизации — гонка за данные (UB). Программа «работала», потому
что планировщик не сводил потоки в опасный момент, но это чистая случайность.

## Исправление

Поле становится атомарным:

```cpp
class interrupt_flag {
public:
    void set() { flag.store(true); }
    bool is_set() const { return flag.load(); }

private:
    std::atomic<bool> flag{false};
};
```

`std::atomic<bool>` использует `memory_order_seq_cst` по умолчанию: запись
`store(true)` становится видимой читающим потокам, а неопределённое поведение
исчезает. Для кооперативного прерывания этого достаточно.

## Почему один общий флаг, а не thread_local

В лекции у каждого потока собственный `thread_local` флаг, и
`interruption_point()` обращается к нему без параметров. Здесь упрощение: один
общий флаг, прерываем сразу все потоки — как при завершении приложения в
лекции (сначала `interrupt()` всем, потом `join`). Гонка от этого не меняется:
флаг по-прежнему пишет один поток, а читают другие.

Упрощение не случайно: ThreadSanitizer **не видит** гонок через `thread_local` —
доступ к TLS компилируется в обращение через специальный регистр, которое TSan
не инструментирует. Для проверки лабы флаг должен лежать в обычной памяти.
Это важный практический факт: «чистый под TSan» код с TLS-флагом всё ещё может
содержать гонку.

## Зачем повторные записи флага

После того как фоновые потоки наработали порог, `main` подаёт сигнал повторно,
пока все потоки не подтвердят остановку (счётчик `finished`). Идемпотентный
сигнал — безопасно; а TSan для надёжного обнаружения гонки нуждается в
повторных записях (одна-единственная запись может «выпасть» из окна
отслеживания). В решении повторные записи не вредят: `store(true)` атомарен.

## Проверка

Стартер (неатомарный `bool`) под TSan: пока фоновые потоки крутятся в цикле
(наработали ≥ 10 млн), `main` многократно пишет флаг — TSan ловит гонку за
`flag`.

Решение под TSan: чисто. Все четыре фоновых потока останавливаются по
прерыванию (join завершается), накопленная работа не меньше порога,
`result = OK`, exit 0.
