# Решение лабы 11.1

## Реализация

Две задачи через `std::async(std::launch::async, ...)`; каждая сообщает о
готовности своим промисом и ждёт общий сигнал `go` (копию `shared_future`).

`push`-задача:

```cpp
push_ready.set_value();
ready.wait();
q.push(42);
```

`pop`-задача:

```cpp
pop_ready.set_value();
ready.wait();
return q.pop();
```

Основной поток ждёт готовности обеих задач (`push_ready.get_future().wait()`,
`pop_ready.get_future().wait()`), затем `go.set_value()` — обе задачи
стартуют «в то время как», гарантированно одновременно.

Финальные проверки:

```cpp
push_done.get();
ok = ok && (pop_done.get() == 42);
ok = ok && q.empty();
```

`pop_done.get()` даёт извлечённое значение (тип фьючерса — `int`), после чего
проверяется равенство 42 и пустота очереди.

## Почему `go`-барьер

Без барьера поток, помещающий данные, может завершиться до запуска потока,
извлекающего их, — тест превратится в последовательный прогон и не проверит
конкурентность. `promise` + `shared_future` гарантируют, что оба потока стоят
на одной «линии старта» и стартуют вместе.

## Обработка исключений

`catch (...)` устанавливает `go.set_value()` и выбрасывает исключение заново:
если одна задача упала, вторая не останется ждать сигнала навсегда (иначе
тест зависнет). `std::async` дополнительно защищает от висящих потоков —
деструктор фьючерса присоединится к задаче при выходе.

## Проверка

Тест проходит: `pop_done.get() == 42`, очередь пуста, `result = OK`, exit 0.
TSan чист (очередь защищена мьютексом; общих изменяемых данных в тесте нет).
