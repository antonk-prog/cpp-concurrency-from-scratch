# Лаба 11.1. Тест очереди с go-барьером
Модуль: 11. Тестирование и отладка многопоточных приложений
Тип: допиши TODO

## Мотивация

Просто запустить два потока — недостаточно: один может завершиться до старта
другого, и «параллельный» тест ничего не проверит. Чтобы гарантировать, что
конкурентный код действительно выполняется одновременно, тест использует
барьер: каждый поток сообщает «я готов» и ждёт общего сигнала `go`
(схема из листинга 11.1).

## Задача

Допиши тест «один `push` + один `pop` на пустой очереди» для потокобезопасной
очереди из модуля 6:

- в задаче `push`: после `ready.wait()` положить значение 42 в очередь;
- в задаче `pop`: после `ready.wait()` извлечь значение и вернуть его;
- финальные проверки: извлечённое значение равно 42, очередь пуста.

## Требования

1. Обе задачи используют `std::async(std::launch::async, ...)`.
2. Каждая задача устанавливает свой промис готовности и ждёт общий
   `shared_future` `go`.
3. Основной поток ждёт готовности обеих задач, затем устанавливает `go`.
4. Финальные проверки: `pop_done.get() == 42` и `q.empty()`.
5. В `catch` — `go.set_value()` и повторная выдача исключения (без висящих
   потоков).
6. Код компилируется без предупреждений; TSan чист; тест завершается успешно
   (exit 0) при корректной реализации.
