# Лаба 11.2. Стресс-тест общего счётчика — средняя
Модуль: 11. Тестирование и отладка многопоточных приложений
Тип: найди и почини

## Мотивация

Стресс-тест прогоняет код многократно, часто с большим числом потоков, чтобы
поймать редкий порядок диспетчеризации. Но успешный прогон — не доказательство:
без правильной синхронизации код может «работать», пока планировщик не сведёт
потоки в опасный момент. ThreadSanitizer ловит гонку сразу, и это часть
тестирования.

## Задача

В стартовом коде стресс-тест: несколько потоков многократно увеличивают общий
счётчик, тест повторяется много раз. Счётчик — обычный `int` → гонка за данные.
Найди ошибку и исправь её. Проверь через ThreadSanitizer, что гонка уходит и
результат всегда корректен.

## Требования

1. Общий счётчик — `std::atomic<int>`; инкремент — через `fetch_add` (или
   `++` на атомарной переменной).
2. Стресс-структура сохраняется: несколько потоков, несколько повторов,
   проверка итогового значения.
3. Код компилируется без предупреждений; TSan чист; программа печатает
   итог и завершается успешно (exit 0).

## Стартовый код

Файлы: `starter/main.cpp`.

Сборка:

```
g++ -std=c++17 -pthread -Wall -Wextra main.cpp -o stress
```

Проверка гонки (на решении должно быть чисто, на стартере — должна ловиться):

```
g++ -std=c++17 -pthread -fsanitize=thread -g -O1 main.cpp -o stress_tsan
./stress_tsan
```

## Чеклист самопроверки

- Нашёл, какая переменная изменяется из нескольких потоков без синхронизации.
- Счётчик стал атомарным; гонка ушла (TSan чист).
- Итоговое значение равно ожидаемому на всех повторах.
