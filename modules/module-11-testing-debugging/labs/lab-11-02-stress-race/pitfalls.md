# Грабли лабы 11.2

## Оставил `int` вместо `std::atomic<int>`

Общий счётчик без атомарности — гонка за данные (UB). Проверяется TSan, а не
«вроде совпало». Потерянные обновления могут не проявиться на однопроцессорной
машине.

## Считал «совпало один раз» доказательством

Стресс-тест даёт ложную уверенность: если проблемные условия не возникли, он
не упадёт никогда. «Прогнал и всё сошлось» — не доказательство; только TSan
(или перебор порядков) даёт детерминированную проверку.

## Использовал `seq_cst`, когда достаточно `relaxed`

`fetch_add` с `relaxed` атомарен — порядок между потоками не нужен. `seq_cst`
тоже корректен, но медленнее; для простого счётчика избыточен.

## Читал счётчик до `join`

Проверять итог нужно после присоединения всех потоков — иначе читаешь ещё не
завершённое значение.

## Не повторил прогон несколько раз

Один проход стресса почти ничего не доказывает. Повторы с разным числом
потоков повышают шанс поймать редкий порядок диспетчеризации.
