# Модуль 11 — Тестирование и отладка многопоточных приложений — ПЛАН

## Допущения модуля

### Прогрессия (что разрешено)
- Всё из модулей 1–10. Ключевые опоры:
  - `std::promise`/`std::future`/`std::shared_future` (м4);
  - потокобезопасная очередь (м6, lab-06-01);
  - атомарные типы, гонка за данные, `memory_order` (м5);
  - инструменты: TSan (`-fsanitize=thread`), стресс-прогоны.
- Новое: методология тестирования конкурентного кода (типы ошибок, просмотр
  кода, стресс-тестирование, структурирование тестов с «go»-барьером,
  тестирование производительности). Примитивов новых нет — только приёмы.
- Запрещено всё из C++20+ (как в остальных модулях).
- Политики выполнения не нужны; реальный параллелизм доступен (потоки).

### Тематика (соответствие главе 11)
Лекция покрывает:
- 11.1 Типы ошибок, связанных с конкурентностью:
  - 11.1.1 нежелательная блокировка (взаимная, активная, блокировка на
    вводе-выводе);
  - 11.1.2 состояния гонки: гонка за данными (UB), нарушение инвариантов,
    проблемы времени жизни; почему симптомы проявляются «не там»;
- 11.2 Приёмы обнаружения ошибок:
  - 11.2.1 просмотр кода: свежий взгляд, вопросы для ревью (какие данные
    защищаем, какие мьютексы удерживаются, валидны ли данные и т.д.);
  - 11.2.2 тестирование: изоляция минимального фрагмента, сведение
    конкурентности к одному потоку, сценарии для очереди, среда тестирования;
  - 11.2.3 разработка с прицелом на тестируемость: отделение «конкурентных»
    частей от «однопоточных», минимизация кода синхронизации;
  - 11.2.4 приёмы: стресс-тестирование (ложная уверенность), комбинационное
    имитационное тестирование, специализированные библиотеки (проверка
    блокировок, запись порядка мьютексов, контроль диспетчеризации);
  - 11.2.5 структурирование тестового кода: настройка → потоковая настройка →
    конкурентный код → финальные проверки; «go»-барьер через
    `promise`/`shared_future` (листинг 11.1), обработка исключений;
  - 11.2.6 тестирование производительности: масштабируемость, закон Амдала,
    прогон на разных машинах.

### Список лаб (тип, название, суть, чему учит)

1. **lab-11-01-concurrent-queue-test (допиши TODO, средняя)**
   - Суть: написать тест «один push + один pop на пустой очереди» через
     «go»-барьер (схема листинга 11.1): два `std::async(std::launch::async)`
     потока ждут общего сигнала `go`; после срабатывания push кладёт значение,
     pop извлекает; финальные `assert`-проверки. Очередь — из модуля 6.
   - Чему учит: структурирование многопоточного теста (настройка/потоки/код
     «в то время как»/финальные проверки), `promise`+`shared_future` как барьер,
     обработку исключений в тесте (go.set_value в catch).
   - Прогрессия: `std::async`/`future`/`promise`/`shared_future` (м4),
     потокобезопасная очередь (м6).

2. **lab-11-02-stress-race (найди и почини, средняя)**
   - Суть: стресс-тест общего счётчика: много потоков инкрементируют общий
     неатомарный `int`, тест повторяется многократно. Баг — гонка за данные;
     TSan ловит. Починить: `std::atomic<int>`.
   - Чему учит: стресс-тестирование (многократные прогоны, много потоков),
     почему «прогон сошёлся» — не доказательство, роль TSan.
   - Прогрессия: `std::atomic` (м5), потоки (м2).

3. **lab-11-03-data-race-ub (предскажи вывод, базовая)**
   - Суть: два потока без синхронизации пишут общую переменную, главный поток
     её печатает. Предсказать вывод программы.
   - Чему учит: гонка за данные — UB, вывод недетерминирован; «иногда 3,
     иногда 2» — симптом; правильный ответ «это UB, предсказать нельзя».
   - Прогрессия: потоки (м2), модель памяти (м5).

## Заголовки лекции (README.md) с 1–2 фразами содержания

1. **Зачем это нужно** — ошибки конкурентности коварны: проявляются редко и
   «не там»; без систематических приёмов их трудно найти.
2. **Типы ошибок (11.1)** — нежелательные блокировки; состояния гонки
   (гонка за данными, инварианты, время жизни); почему сбои блуждают по коду.
3. **Просмотр кода (11.2.1)** — свежий взгляд, вопросы для ревью, «сыщик»
   от строки к причине.
4. **Тестирование (11.2.2)** — минимальный фрагмент, сведение к одному потоку,
   сценарии очереди, среда (число потоков, ядер, архитектур).
5. **Тестируемость (11.2.3)** — отделение конкурентных частей от
   однопоточных; меньше синхронизации = проще тесты.
6. **Стресс-тестирование (11.2.4)** — многократные прогоны, ложная
   уверенность, однопроцессорная ловушка, архитектуры.
7. **Комбинационное имитационное тестирование (11.2.4)** — перебор допустимых
   порядков операций по модели памяти; дорого, для малых фрагментов.
8. **Специализированные библиотеки (11.2.4)** — проверка блокировок,
   запись порядка мьютексов (потенциальные deadlock), контроль
   диспетчеризации.
9. **Структурирование теста (11.2.5)** — четыре части теста; «go»-барьер
   через `promise`/`shared_future` (листинг 11.1); обработка исключений.
10. **Тестирование производительности (11.2.6)** — масштабируемость,
    закон Амдала, прогон на разных системах.
11. **Типичные ошибки** — «работает на моей машине», тест без go-барьера,
    ложная уверенность стресса, забытые исключения в тесте.
12. **Шпаргалка** — таблица: приём, что даёт, ограничения.
