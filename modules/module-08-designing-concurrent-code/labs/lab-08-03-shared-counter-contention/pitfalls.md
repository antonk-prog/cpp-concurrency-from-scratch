# Грабли лабы 8.3

## Собрал без `-O2`

Эффект конкуренции проявится только на оптимизированной сборке. Без `-O2`
замеры шумные, и вывод может быть случайным.

## Сравнил режимы с разным суммарным объёмом работы

Один поток должен делать столько же итераций, сколько в сумме все потоки
(`threads * n` против `threads` потоков по `n`). Иначе «быстрее/медленнее»
не про что сравнивать.

## Один повторитель, один замер

Один замер — лотерея (фоновые процессы, троттлинг, миграция потоков). Бери
лучшее из нескольких повторов.

## Считал `relaxed` «не атомарным»

`fetch_add` с `memory_order_relaxed` — по-прежнему операция
«чтение-изменение-запись», ей нужна свежая строка кэша. Порядок памяти тут
ни при чём: конкуренция — про аппаратуру, а не про ordering.

## Думал, что больше потоков всегда быстрее

Нет: при конкуренции за общие данные несколько потоков могут быть в десятки
раз медленнее одного. Это и есть урок лабы — измеряй, а не предполагай.

## Выровнял начало массива вместо элементов

`alignas` на массив выровняет только его начало — счётчики всё равно окажутся
в одной строке кэша. Выравнивать нужно каждый элемент (структура-обёртка с
`alignas` вокруг одного атомарного счётчика).

## Не объяснил «работает на 10, ломается на 1000»

Ключ: перебрасывание строки кэша стоит сотни тактов на каждое обращение. Пока
итераций мало, суммарная цена перебрасывания тонет в общем времени; при
большом числе итераций она становится главным фактором.
