# Подсказка 1 — направление мысли

Подумай, что аппаратно делает `counter.fetch_add(1)`:

- это операция «чтение-изменение-запись»: процессору нужна «свежая» строка
  кэша, содержащая `counter`;
- если её держит другое ядро (потому что другой поток тоже увеличивает
  счётчик), ядро обязано дождаться передачи строки;
- чем больше потоков конкурируют за один счётчик, тем чаще строка кэша
  «курсирует» между ядрами — каждый шаг любого потока инвалидирует её для всех
  остальных.

Пока итераций мало, суммарное время мало и перебрасывание тонет в шуме.
На сотнях миллионов итераций перебрасывание становится доминирующим фактором —
отсюда десятки раз проигрыша.

Что нужно, чтобы потоки не конкурировали за одну и ту же строку кэша?
