# Решение лабы 8.3

## Что происходит в стартовом коде

Все потоки увеличивают один и тот же атомарный счётчик `counter`.
`fetch_add` — операция «чтение-изменение-запись»: процессору нужна «свежая»
строка кэша, содержащая счётчик. Если строку держит другое ядро, ядро обязано
дождаться её передачи — а передача строки кэша между ядрами стоит сотни тактов.

Каждый шаг любого потока инвалидирует строку кэша для всех остальных: потоки
постоянно «перебрасывают» её друг другу. Чем больше потоков конкурируют за
один счётчик, тем хуже. Это конкуренция при обращении к данным — один из
главных факторов деградации конкурентного кода (раздел 8.2.2 лекции).

## Предсказание и результат

Ожидание: **несколько потоков с общим счётчиком медленнее одного потока**,
хотя суммарной работы поровну. Причина — перебрасывание строки кэша.

Почему это «нагрузочный вопрос»: на 10 итерациях перебрасывание строки — это
сотни тактов на фоне микросекунд общей работы, разница тонет в шуме. На 100
миллионов итераций перебрасывание становится доминирующим фактором, и общий
счётчик проигрывает в десятки раз. «Работает на малом, ломается на большом».

Типичный замер на 4 ядрах (машина автора):

```
1 поток, общий счётчик        : 2400 ms
4 потока, общий счётчик        : 11000 ms
```

## Исправление

Делим работу так, чтобы потоки не конкурировали за одну строку кэша:
у каждого потока свой счётчик, выровненный по отдельной строке кэша через
`std::hardware_destructive_interference_size` (заголовок `<new>`):

```cpp
struct item {
    alignas(std::hardware_destructive_interference_size) std::atomic<long> v;
};
std::vector<item> counters(threads);
```

Поток `i` увеличивает `counters[i].v` — строку кэша ни с кем не делит,
перебрасывания нет:

```
1 поток, общий счётчик        : 2400 ms
4 потока, общий счётчик        : 11000 ms
4 потока, свои счётчики        : 620 ms
```

Свои счётчики дают выигрыш в 15+ раз по сравнению с общим. При реальном
суммировании останется лишь этап сведения — сложить свои счётчики в конце
(это последовательный этап, из раздела 8.1).

## Проверка

Каждый поток обращается только к «своему» атомарному счётчику — гонки за
данные нет, TSan чист. Программа печатает времена и завершается с exit 0.
Цифры зависят от архитектуры: с одним физическим ядром (VM) выигрыша может не
быть вовсе, с несколькими ядрами он гарантирован. Измеряй на целевой системе.
