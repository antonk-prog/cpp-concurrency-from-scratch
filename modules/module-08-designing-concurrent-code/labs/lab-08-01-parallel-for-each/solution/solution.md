# Решение лабы 8.1

## Реализация

**`join_threads`** — RAII-обёртка, присоединяющая все потоки в деструкторе.
Развитие `thread_guard` из модуля 2 на весь вектор:

```cpp
class join_threads {
    std::vector<std::thread>& threads;
public:
    explicit join_threads(std::vector<std::thread>& t) : threads(t) {}
    ~join_threads() {
        for (auto& th : threads) {
            if (th.joinable()) th.join();
        }
    }
};
```

Объект создаётся сразу после векторов `futures` и `threads`, поэтому при любом
выходе из функции — нормальном или по исключению — деструктор присоединит все
потоки, которые ещё не завершились. Так мы избегаем `std::terminate` при
уничтожении `std::thread`.

**`parallel_for_each`** — разбиение диапазона на смежные блоки:

1. `length = std::distance(first, last)`; при пустом диапазоне — выход.
2. Число потоков: минимум из `hardware_concurrency()` и числа блоков по
   25 элементов. Это защищает от порождения лишних потоков при малом
   диапазоне.
3. `block_size = length / num_threads` — смежные блоки (чтобы не провоцировать
   ложное совместное использование и дать кэшу «работать» по близким данным).
4. Для каждого блока, кроме последнего, создаётся
   `std::packaged_task<void(void)>`, захватывающая блок по значению; фьючерс
   сохраняется, задача перемещается в новый поток через `std::move`.
5. Последний блок обрабатывается в текущем потоке.
6. `futures[i].get()` для каждого фьючерса: `get()` блокирует до завершения
   задачи и повторно выдаёт исключение, если задача его бросила.

## Почему `packaged_task` + `future`

Рабочие потоки значений не возвращают, но исключения должны дойти до
вызывающего кода. `std::packaged_task` перехватывает исключение из `f` и
сохраняет его во фьючерсе; `get()` в основном потоке выдаёт его заново. Без
этого исключение в рабочем потоке упало бы через `std::terminate`.

`std::packaged_task` — move-only, поэтому хранить его в очереди задач
(как в пуле потоков из модуля 9) напрямую нельзя — понадобится обёртка. Здесь
мы передаём задачу сразу в `std::thread`, поэтому `std::move(task)` достаточно.

## Почему `join_threads` отдельно

Цикл `join` в конце функции дублировал бы логику на случай исключения
(try-catch). RAII-обёртка убирает дублирование и гарантирует присоединение
потоков в любом случае. Дополнительно `futures[i].get()` и так ждёт завершения
задач, так что `join_threads` — подстраховка на случай исключения до `get()`.

## Проверка

Программа умножает все 100 000 элементов на 2 и проверяет, что каждый стал
ровно `2*i`. TSan чист: каждый элемент обрабатывается ровно одним потоком,
общих записываемых данных нет.
