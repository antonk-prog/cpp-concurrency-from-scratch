# Грабли лабы 8.2

## Оставил `bool` вместо `std::atomic<bool>`

Общий флаг, который читают несколько потоков, а пишет один — неатомарная
переменная → гонка за данные (UB). Исправляется `std::atomic<bool>` +
`load()`/`store()`. Проверяй TSan, а не «вроде работает».

## Забыл `load()` в цикле

`!done_flag` на атомарном указателе не компилируется (нужно `->load()`), но
если написать `!*done_flag` — это уже обращение к неатомарному значению под
капотом. Всегда `done_flag->load()`.

## Поставил искомый элемент в конец диапазона

Тогда его найдёт последний поток (главный, обрабатывающий последний блок) в
самый последний момент — остальные потоки могут успеть закончить, и TSan не
поймает гонку. Искомое должно лежать в начале, чтобы писатель работал, пока
остальные ещё сканируют. Несколько повторов поиска делают гонку ещё надёжнее.

## Считал «гонку за promise» проблемой

`set_value` из двух потоков — не гонка за данные: `std::promise`
потокобезопасен, второй вызов просто бросает исключение. Обработка в
`catch (...)` корректна.

## Проверил `done_flag` до join

Если проверять флаг до присоединения потоков, можно прочитать ещё не
установленное значение и неправильно вернуть `last`. Сначала join всех, потом
проверка.

## Думал, что ранняя остановка не нужна

Без флага параллельный `find` обгонял бы последовательный при раннем
совпадении (перебирал бы весь диапазон). Флаг — суть алгоритма: останавливай
потоки, как только ответ найден.
