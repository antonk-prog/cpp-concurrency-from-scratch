# Модуль 8 — Разработка конкурентного кода — ПЛАН

## Допущения модуля

### Прогрессия (что разрешено)
- Всё из модулей 1–7. Ключевые опоры:
  - `std::thread`, RAII-обёртки, `parallel_accumulate` (модуль 2);
  - мьютексы, `condition_variable` (модули 3–4);
  - `std::async`, `std::packaged_task`, `std::promise`, `std::future`
    (модуль 4);
  - атомарные типы, `memory_order` (модуль 5);
  - потокобезопасный стек (модуль 6, листинг 6.x / лаба).
- `join_threads` (класс, присоединяющий все потоки в деструкторе) — вводится
  в ЭТОМ модуле (из главы 8) как развитие `thread_guard` из модуля 2.
- Собственный спин-барьер (листинг 8.12) — на атомарных операциях модуля 5;
  `std::barrier` из C++20 НЕ используется (запрещён ground). Concurrency TS
  (`std::experimental::barrier`) — только упоминание, без использования.
- `std::hardware_destructive_interference_size` / `constructive_interference_size`
  — C++17, `<new>`; допустимы, вводятся в лекции.
- Модуль 9 (пулы потоков) ещё не написан: понятия пула не вводить, кроме
  краткой отсылки «подробнее позже».
- Запрещено всё из C++20+: `std::jthread`, `std::counting_semaphore`,
  `std::barrier`, `std::latch`, корутины, `std::format`, execution policies
  (`std::execution::par` — это тема главы 10/модуля 10).

### Тематика (соответствие главе 8)
Лекция покрывает:
- 8.1 Способы распределения работы между потоками:
  - 8.1.1 распределение данных до начала обработки (блоки, рис. 8.1),
    этап сведения, почему не подходит для рекурсивных алгоритмов;
  - 8.1.2 рекурсивное распределение (Quicksort, рис. 8.2), `std::async`,
    проблема неограниченного числа потоков, стек фрагментов (листинг 8.1),
    ограничение по `hardware_concurrency()`, конкуренция за стек;
  - 8.1.3 распределение работы по типам задач: специализация потоков,
    конвейер (pipeline), пример обработки видео;
- 8.2 Факторы, влияющие на производительность:
  - 8.2.1 число процессоров и `hardware_concurrency()`, переоценка
    вычислительных возможностей (oversubscription);
  - 8.2.2 конкуренция при обращении к данным и перебрасывание данных
    в кэш-памяти (пример с `fetch_add`, мьютексом);
  - 8.2.3 ложное совместное использование (cache line),
    `std::hardware_destructive_interference_size`;
  - 8.2.4 близость данных к потоку, `constructive_interference_size`,
    переключения задач;
  - 8.2.5 переоценка вычислительных возможностей и чрезмерные переключения;
- 8.3 Разработка структур данных для высокопроизводительных приложений:
  - 8.3.1 распределение элементов массива (перемножение матриц, рис. 8.3:
    строки/столбцы/блоки, объём чтения);
  - 8.3.2 схемы доступа в других структурах (деревья, мьютекс и данные,
    padding-проверка);
- 8.4 Дополнительные факторы:
  - 8.4.1 безопасность исключений в параллельных алгоритмах (анализ
    листинга 8.2 → `packaged_task` 8.3 → `join_threads` 8.4 → `std::async` 8.5);
  - 8.4.2 масштабируемость и закон Амдала (формула);
  - 8.4.3 компенсация потерь на ожидание (I/O-bound потоки);
  - 8.4.4 повышение отзывчивости (GUI-поток + задача, листинг 8.6);
- 8.5 Разработка конкурентного кода на практике:
  - 8.5.1 параллельный `std::for_each` (листинги 8.7, 8.8);
  - 8.5.2 параллельный `std::find` (листинги 8.9, 8.10, флаг остановки);
  - 8.5.3 параллельный `std::partial_sum` (листинги 8.11, 8.12, 8.13,
    барьер, попарные обновления).

### Список лаб (тип, название, суть, чему учит)

1. **lab-08-01-parallel-for-each (напиши с нуля, средняя)**
   - Суть: реализовать `parallel_for_each` — разбиение диапазона на блоки,
     порождение потоков через `std::packaged_task`+`std::future`, сбор
     исключений через `get()`, гарантированный join через `join_threads`
     (RAII-класс написать самому).
   - Чему учит: распределение данных до обработки, безопасность исключений
     в параллельных алгоритмах, RAII вместо try-catch.
   - Прогрессия: `packaged_task`/`future` (м4), `std::thread` (м2),
     `join_threads` (м8).

2. **lab-08-02-find-done-flag (найди и почини, средняя)**
   - Суть: параллельный `find`: общий флаг «найдено» объявлен как обычный
     `bool`, пишется из рабочих потоков, читается другими → гонка за данные,
     ловится TSan. Починить: `std::atomic<bool>`; проверить, что ранняя
     остановка работает и результат корректен.
   - Чему учит: почему флаг остановки обязан быть атомарным; прерывание
     работы других потоков при раннем завершении алгоритма.
   - Прогрессия: `std::atomic` (м5), `std::promise`/`future` (м4).

3. **lab-08-03-shared-counter-contention (нагрузочный вопрос, сложная)**
   - Суть: бенчмарк: общий атомарный счётчик, который увеличивают все потоки.
     На малом числе итераций разница не видна, на больших (100 млн на поток)
     общий счётчик проигрывает однопоточному в десятки раз (перебрасывание
     строки кэша между ядрами). Объяснить, почему, затем починить: каждый
     поток — свой выровненный счётчик через
     `std::hardware_destructive_interference_size`, измерить улучшение.
   - Чему учит: конкуренция при обращении к данным (8.2.2) — главный фактор
     деградации; перебрасывание строки кэша; разделение данных между потоками
     вместо общего счётчика.
   - Прогрессия: `std::atomic` (м5), `hardware_destructive_interference_size`
     (м8), измерение времени.
   - Примечание: тема заменена с «ложного совместного использования» — на
     текущем оборудовании (VM, 4 физических ядра) false sharing недемонстрируем,
     эффект конкуренции за счётчик воспроизводится стабильно (решение
     пользователя 2026-09-09).

## Заголовки лекции (README.md) с 1–2 фразами содержания

1. **Зачем это нужно** — конкурентный код проектируют: сколько потоков,
   как распределить работу, как не потерять производительность.
2. **Распределение данных до обработки (8.1.1)** — блоки элементов, этап
   сведения, рис. 8.1; почему не работает для рекурсивных алгоритмов.
3. **Рекурсивное распределение (8.1.2)** — Quicksort, `std::async`, рис. 8.2,
   стек фрагментов (листинг 8.1), ограничение потоков, конкуренция за стек.
4. **Распределение по типам задач (8.1.3)** — специализация потоков,
   конвейер, пример видео.
5. **Сколько процессоров? (8.2.1)** — `hardware_concurrency()`, переоценка
   вычислительных возможностей.
6. **Конкуренция за данные и кэш (8.2.2)** — перебрасывание данных в кэш-памяти,
   примеры с атомарным счётчиком и мьютексом.
7. **Ложное совместное использование (8.2.3)** — строки кэша,
   `hardware_destructive_interference_size`.
8. **Близость данных (8.2.4)** — `constructive_interference_size`,
   переключение задач.
9. **Переоценка вычислительных возможностей (8.2.5)** — слишком много готовых
   потоков, издержки переключений.
10. **Структуры данных (8.3)** — перемножение матриц: строки/столбцы/блоки,
    рис. 8.3; деревья и мьютекс рядом с данными, padding-проверка.
11. **Безопасность исключений (8.4.1)** — анализ параллельного `accumulate`,
    `packaged_task`, `join_threads`, `std::async` (листинги 8.2–8.5).
12. **Масштабируемость и закон Амдала (8.4.2)** — формула, следствия.
13. **Компенсация ожидания и отзывчивость (8.4.3–8.4.4)** — I/O-bound потоки,
    GUI + фоновая задача (листинг 8.6).
14. **Практика: for_each (8.5.1)** — листинги 8.7, 8.8.
15. **Практика: find (8.5.2)** — листинги 8.9, 8.10, флаг остановки.
16. **Практика: partial_sum (8.5.3)** — листинги 8.11–8.13, барьер.
17. **Типичные ошибки** — неатомарный флаг остановки; join при исключении;
    ложное совместное использование; слишком много потоков; порядок
    обработки элементов.
18. **Шпаргалка** — таблица: приём, где применяется, что даёт.
