# Грабли лабы 5.1

## Забыл проинициализировать flag через ATOMIC_FLAG_INIT

`std::atomic_flag` без `ATOMIC_FLAG_INIT` находится в неопределённом состоянии.
Инициализируй его в списке инициализации: `: flag(ATOMIC_FLAG_INIT)`. Это
единственный атомарный тип с особым требованием к инициализации.

## Использовал relaxed вместо acquire/release

Если в `lock()`/`unlock()` указать `memory_order_relaxed`, пара «синхронизируется
с» не установится. Поток, захвативший блокировку, может не увидеть изменения
защищённых данных, сделанные предыдущим владельцем, — это гонка за данные (UB).
`lock()` — захват (`acquire`), `unlock()` — освобождение (`release`).

## Не тот порядок операций в lock()

Важно: цикл `while (flag.test_and_set(acquire));` — крутится, **пока** результат
`true`. Новички пишут `while (!flag.test_and_set(...))`, что семантически
переворачивает логику: поток будет «владеть» блокировкой, когда флаг уже был
установлен другим потоком. Аккуратно с инверсией.

## Не дождался потоков через join()

`main` завершится раньше рабочих потоков, и они могут не успеть отработать —
результат непредсказуем. Каждый `std::thread` обязан быть присоединён через
`join()` (или отсоединён через `detach()`) до разрушения объекта.

## Проверял корректность «на глаз», без запусков

Спин-блокировка корректна, только если финальный счётчик сходится к ожидаемому
значению при многократных запусках. Прогони с `-fsanitize=thread`: TSan должен
быть чист на корректном решении и ловить гонку, если упорядочение неверное.
