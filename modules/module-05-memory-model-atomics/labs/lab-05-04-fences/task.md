# Лаба 5.4. Барьеры памяти для передачи данных
Модуль: 5. Модель памяти и атомарные операции
Тип: допиши TODO

## Мотивация

В реальном коде данные и флаг готовности — это часто разные переменные:
обычный массив и атомарный флаг. Сам по себе `memory_order_relaxed` для флага
ничего не упорядочивает, поэтому чтение массива после установки флага — гонка
за данные. Упорядочение можно навязать **барьерами памяти**
(`std::atomic_thread_fence`), не меняя атомарных операций над самим флагом.

## Задача

В стартовом коде писатель заполняет массив `data`, затем публикует флаг
`ready` (нестрого, `relaxed`). Читатель ждёт флаг и проверяет массив.
Дополни два `TODO`: вставь **барьер освобождения** (release) в писателе перед
публикацией готовности и **барьер захвата** (acquire) в читателе после того,
как флаг стал `true`.

## Требования

1. Барьер освобождения (`std::atomic_thread_fence(std::memory_order_release)`)
   стоит в `writer()` строго после записи всех элементов `data` и до
   `ready.store(...)`.
2. Барьер захвата (`std::atomic_thread_fence(std::memory_order_acquire)`)
   стоит в `reader()` строго после выхода из цикла ожидания `ready` и до
   чтения `data`.
3. Программа печатает `OK` и завершается с кодом 0 — все элементы массива
   читатель увидел корректно.
4. Код компилируется без предупреждений и стабильно печатает `OK` при
   многократных запусках. (TSan не поддерживает `std::atomic_thread_fence`
   и может выдать ложную гонку даже на корректном решении — об этом ниже
   в `solution/solution.md`.)
