# Лаба 5.5. Публикация объекта через std::atomic<T*>
Модуль: 5. Модель памяти и атомарные операции
Тип: напиши с нуля

## Мотивация

Классический способ передать объект между потоками — опубликовать на него
указатель. Атомарный указатель `std::atomic<T*>` позволяет сделать это без
блокировок: писатель кладёт объект в кучу и публикует указатель с `release`,
а читатели забирают его с `acquire`. Главное — чтобы читатель увидел
**полностью инициализированный** объект, а не «полусобранный».

## Задача

С нуля реализуй `producer()` и `consumer()` в стартовом коде. Писатель создаёт
`Payload`, заполняет поля и публикует указатель через `std::atomic<Payload*>
published`. Каждый читатель дожидается публикации, проверяет поля и пишет
результат в свой `bool`. Используй пару acquire/release, а не `consume`.

## Требования

1. `producer()` создаёт `Payload{7, "hello"}` и публикует указатель через
   `published.store(p, std::memory_order_release)`.
2. `consumer()` ждёт, пока `published` станет непустым (загрузка с
   `std::memory_order_acquire`), затем проверяет, что `id == 7`
   и `text == "hello"`, и записывает результат в `*ok`.
3. Поля `Payload` не читаются до публикации; `memory_order_consume`
   не используется.
4. Программа печатает `OK` и завершается с кодом 0 — все читатели увидели
   корректные поля.
5. Код компилируется без предупреждений; TSan не находит гонок.

## Стартовый код

Файлы: `starter/main.cpp`.

Сборка:

```
g++ -std=c++17 -pthread -Wall -Wextra main.cpp -o publish
```

Стартовый код не завершится, пока `producer()` и `consumer()` не реализованы:
потребители в нём вечно ждут публикации. Это нормально для лабы «напиши
с нуля» — реализуй функции, и программа начнёт отрабатывать.
