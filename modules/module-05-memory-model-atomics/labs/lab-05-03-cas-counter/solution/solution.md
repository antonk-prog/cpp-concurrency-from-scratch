# Решение лабы 5.3

## Реализация

Ключевой приём — **CAS-цикл**: инкремент/декремент выполняются не готовым
атомарным оператором, а через `compare_exchange_strong` в цикле.

```cpp
void increment() {
    int expected = value_.load();
    while (!value_.compare_exchange_strong(expected, expected + 1)) {
        // expected обновлён; пробуем снова
    }
}
```

## Почему это корректно

`compare_exchange_strong(expected, desired)` атомарно делает следующее:
сравнивает текущее значение с `expected`; если равны — записывает `desired`
и возвращает `true`; если нет — записывает в `expected` актуальное значение
и возвращает `false`.

В цикле возможен один сценарий неудачи: **другой поток изменил счётчик** между
`load()` и CAS. Тогда сравнение не сходится, `expected` обновляется до актуального
значения, и цикл повторяет попытку уже с новым `expected`. Значение не теряется:
каждый поток «дожимает» свою операцию до успеха.

`strong` удобен тем, что возвращает `false` **только** при реальном несовпадении
значений — ложного сбоя, как у `weak`, у него нет. В цикле это проще для
рассуждений: каждый возврат `false` означает «кто-то другой успел изменить
счётчик», и нужно просто пересчитать `desired` с новым `expected`. Цена — на
платформах без аппаратной инструкции CAS `strong` может быть реализован через
внутренний цикл, но для учебного примера это не важно.

## Почему используется seq_cst

По умолчанию все атомарные операции используют `memory_order_seq_cst` —
самый строгий порядок. Для этого счётчика достаточно и `relaxed` (каждая операция
независима, между ними нет передачи данных), но `seq_cst` проще и на x86 почти
не дороже. В реальном коде счётчик вроде этого обычно делают `relaxed`.

## Проверка

Финальное значение равно 0, потому что каждое `increment()` скомпенсировано
`decrement()` тем же потоком, а CAS-цикл гарантирует атомарность каждого шага.
При 8 потоках × 100000 итераций счётчик всегда сходится к 0; TSan чист.

## Куда это ведёт

Такой же CAS-цикл лежит в основе операций, для которых нет готового атомарного
оператора (умножение, сдвиг, сложные обновления структуры) и структур данных
без блокировок (глава 7). А когда CAS-цепочка используется для синхронизации
нескольких потребителей (например, цепочка `store(release) → fetch_sub(acquire) →
fetch_sub(acquire)`), на помощь приходят последовательности освобождений
(release sequences).
