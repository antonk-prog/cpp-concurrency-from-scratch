# Грабли лабы 5.6

## Опубликовал count до заполнения items

`count.store(release)` обязан стоять **после** записи `items`: release
«публикует» всё, что записано до него. Иначе потребитель может получить
элемент, которого ещё не существует (данные не готовы).

## Использовал relaxed для store или fetch_sub

`relaxed` не создаёт отношения «синхронизируется с». Если `store` или
`fetch_sub` нестрогие, чтение `items` потребителем — гонка за данные (UB).
Нужна пара release (публикация) + acquire (забор).

## Обработал элемент при v <= 0

При `v <= 0` элемента нет: значение `0` уже не принадлежит опубликованной
партии. Обрабатывать нужно только индексы `v - 1 >= 0`.

## Проверял только «по поведению», без TSan

На x86 гонка за `items` часто «не видна» на глаз (порядок почти всегда
совпадает). Прогони `-fsanitize=thread`: корректная версия должна быть чистой,
а версия с `relaxed` — срабатывать.
