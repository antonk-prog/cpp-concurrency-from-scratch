# Решение лабы 5.2

## Ошибка

В стартовом коде две взаимосвязанные ошибки, обе приводят к гонке за данные
(неопределённое поведение):

1. **Флаг выставлялся до завершения записи.** `ready.store(true, ...)` стоял
   на первой итерации цикла записи (`if (i == 0)`). Значит, читатель, увидев
   флаг, мог начать читать `data`, пока писатель ещё заполнял остальные элементы.
2. **Использовалось `memory_order_relaxed`.** Даже если бы флаг ставился в конце,
   нестрогое упорядочение не создаёт отношения «синхронизируется с» между
   записью данных и их чтением.

## Исправление

Писатель сначала полностью записывает данные, затем ставит флаг как
**освобождение**:

```cpp
for (int i = 0; i < n; ++i) data[i] = i + 1;
ready.store(true, std::memory_order_release);   // освобождение
```

Читатель ждёт флаг как **захват**:

```cpp
while (!ready.load(std::memory_order_acquire)) { }
```

## Почему это работает

Выстраивается цепочка отношения «происходит до»:

1. запись `data[i]` происходит до `ready.store(true, release)` — один поток,
   порядок в коде;
2. `ready.store(true, release)` синхронизируется с `ready.load()` (acquire),
   когда тот увидел `true`, — операция освобождения синхронизируется с захватом;
3. `ready.load()` происходит до чтения `data[i]` — один поток, порядок в коде.

По транзитивности запись `data` происходит до чтения `data` — принудительный
порядок установлен, гонки за данные нет.

## Что оставить relaxed

Переменная `ok` — независимый флаг результата, читаемый только после `join()`
обоих потоков, а `join()` сам по себе синхронизирует. Поэтому для `ok` безопасно
оставить `relaxed`: там нет передачи данных между потоками «на лету».

## Проверка

С `-fsanitize=thread` решение чисто. Стартовый код TSan ловит data race на
`data` (писатель пишет, читатель читает параллельно).
