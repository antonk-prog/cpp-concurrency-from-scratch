# Лаба 5.2. Почини гонку из-за нестрогого упорядочения
Модуль: 5. Модель памяти и атомарные операции
Тип: найди и почини

## Мотивация

`memory_order_relaxed` даёт минимум гарантий: он не создаёт отношения
«синхронизируется с» и не упорядочивает операции над разными переменными.
Если использовать его там, где один поток передаёт данные другому через флаг
готовности, получается гонка за данные (неопределённое поведение), которая
проявляется не всегда и потому особенно опасна.

## Задача

В стартовом коде поток-писатель кладёт данные в массив и выставляет атомарный
флаг готовности, поток-читатель ждёт флаг и читает данные. Но упорядочение
выбрано неверно (`relaxed`), из-за чего чтение данных не упорядочено с их
записью — гонка за данные.

Найди ошибку и исправь её, применив корректную пару упорядочения
(захват-освобождение). Не меняй логику и структуру программы.

## Требования

1. Писатель пишет неатомарный массив `data`, затем атомарно выставляет флаг
   `ready` так, чтобы запись данных гарантированно произошла до установки флага.
2. Читатель ждёт `ready == true`, затем читает `data`.
3. Между записью `data` и чтением `data` должно быть установлено отношение
   «происходит до».
4. Программа корректно печатает сумму всех элементов массива.
5. Код компилируется без предупреждений; TSan не находит гонку за данные.

## Стартовый код

Файлы: `starter/main.cpp`.

Сборка:

```
g++ -std=c++17 -pthread -Wall -Wextra main.cpp -o ordering
```

Проверка гонки (у тебя в решении должно быть чисто):

```
g++ -std=c++17 -pthread -fsanitize=thread -g main.cpp -o ordering_tsan
./ordering_tsan
```
