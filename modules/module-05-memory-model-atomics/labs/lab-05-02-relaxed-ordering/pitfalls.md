# Грабли лабы 5.2

## Поставил флаг готовности до завершения записи данных

Если флаг `ready` выставляется раньше, чем данные полностью записаны, читатель
может начать чтение, пока писатель ещё пишет, — это гонка за данные. Сначала
полностью запиши данные, потом выставляй флаг.

## Думал, что relaxed достаточно для передачи данных

`relaxed` гарантирует лишь модификационный порядок одной переменной в одном
потоке. Он не упорядочивает операции над разными переменными и не создаёт
«синхронизируется с». Для передачи данных нужна пара acquire/release (или
seq_cst).

## Исправил упорядочение только у писателя (или только у читателя)

Синхронизация — парная операция. Нужно `release` у писателя **и** `acquire`
у читателя. Если одна сторона осталась на `relaxed`, отношения «синхронизируется
с» не возникает.

## Проверял только «по поведению» без TSan

Гонка за данные — это UB; она может «работать» годами и сломаться в любой
момент. Поведенческая проверка (сумма сходится) не доказывает корректность.
Обязательно прогони `-fsanitize=thread`: на стартовом коде он ловит гонку,
на решении — чист.

## Оставил relaxed там, где он важен

`relaxed` — не «всегда плохо». Он подходит для независимых счётчиков и флагов,
не несущих данные между потоками (например, результат после `join()`). Важно
понимать, где передача данных, а где — нет.
