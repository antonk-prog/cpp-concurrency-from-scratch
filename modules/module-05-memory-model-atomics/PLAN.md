# Модуль 5 — Модель памяти и атомарные операции — ПЛАН

## Допущения модуля

### Прогрессия (что разрешено)
- Примитивы модулей 1–4 (потоки, мьютексы, условные переменные, фьючерсы) —
  уже введены, доступны как «ранее изученное». Но задачи модуля 5 строятся
  на **атомарных операциях и упорядочении памяти** — это суть главы; мьютексы
  в лабах не использовать там, где их роль берут на себя атомарные примитивы.
- Новые примитивы модуля 5: `<atomic>` — `std::atomic_flag`,
  `std::atomic<bool>`, `std::atomic<T*>`, `std::atomic<целочисленные>`,
  `std::atomic<UDT>` (primary template), `load/store/exchange/compare_exchange/
  fetch_*`, `std::atomic_thread_fence`, `std::atomic<T>::is_lock_free`,
  свободные `std::atomic_*` функции.
- `std::memory_order`: `seq_cst`, `relaxed`, `acquire`, `release`, `acq_rel`,
  `consume`.
- Запрещено всё из C++20+: `std::jthread`, `std::counting_semaphore`,
  `std::barrier`, `std::latch`, корутины, `std::format`. Атомарные `wait/notify`
  (C++20) не использовать.
- Concurrency TS (`std::experimental::atomic_shared_ptr`) — только лекционно
  (упоминание), в лабах не применять (правило A014 / «для лаб — примитивы,
  которые гарантированно компилируются»).

### Тематика (соответствие главе 5)
Лекция покрывает:
- 5.1 Основы модели памяти: объекты и области памяти, гонка за данными,
  очередность внесения изменений (modification order).
- 5.2 Атомарные типы и операции: `atomic_flag`, `atomic<bool>`,
  compare_exchange_weak/strong (CAS), `atomic<T*>`, целочисленные,
  primary `atomic<UDT>`, свободные функции.
- 5.3 Синхронизация: «синхронизируется с», «происходит до» (happens-before),
  три модели упорядочения (seq_cst / acquire-release / relaxed), consume
  (кратко, «не использовать»), последовательности освобождений
  (release sequences), барьеры (fences), упорядочение неатомарных операций
  через атомарные.

### Список лаб (тип, название, суть, чему учит)

1. **lab-05-01-spinlock (допиши TODO, базовая/средняя)**
   - Суть: дописать спин-блокировку на `std::atomic_flag` (`test_and_set` +
   `clear`), защитить ей общий счётчик в нескольких потоках.
   - Чему учит: `atomic_flag`, семантика acquire (lock) / release (unlock),
   разница между активным ожиданием и мьютексом.
   - Прогрессия: только атомарные примитивы + потоки модуля 1.

2. **lab-05-02-relaxed-ordering (найди и почини, средняя)**
   - Суть: дан код, где писатель пишет неатомарный флаг/данные, а читатель
   ждёт через `relaxed`-атомар — гонка, assert/некорректное поведение.
   Починить, применив корректное упорядочение (acquire/release).
   - Чему учит: почему relaxed не достаточно для передачи данных между
   потоками, пара acquire/release, «происходит до».
   - Прогрессия: атомарные load/store с memory_order.

3. **lab-05-03-atomic-counter-cas (напиши с нуля, сложная)**
   - Суть: реализовать атомарный счётчик через `compare_exchange_weak`
   (цикл CAS), без `fetch_add`, — либо потокобезопасную структуру (например,
   atomic-очередь/список по мотивам листинга 5.11 с release sequences).
   - Чему учит: CAS-цикл, compare_exchange_weak vs strong, ложный сбой,
   release sequences.
   - Прогрессия: атомарные операции + материал 5.3.4.

## Заголовки лекции (README.md) с 1–2 фразами содержания

1. **Зачем это нужно** — низкоуровневая синхронизация без мьютексов; почему
   нужна модель памяти; когда атомарные операции нужны, а когда нет
   (структуры без блокировок — гл. 7).

2. **Основы модели памяти (5.1)** — объекты и области памяти; что такое
   гонка за данными (UB); очередность внесения изменений (modification order).

3. **Атомарные типы и операции (5.2)** — `<atomic>`, `atomic_flag`,
   `atomic<bool>`, load/store/exchange, CAS (weak/strong), `atomic<T*>`,
   целочисленные fetch_*, primary `atomic<UDT>`, свободные функции.

4. **Синхронизация: «синхронизируется с» и «происходит до» (5.3.1–5.3.2)** —
   два ключевых отношения модели памяти, транзитивность.

5. **Три модели упорядочения (5.3.3)** — seq_cst (по умолчанию), relaxed,
   acquire/release (acq_rel), consume (кратко, не применять).

6. **Последовательности освобождений и барьеры (5.3.4–5.3.5)** —
   release sequences, `std::atomic_thread_fence`.

7. **Упорядочение неатомарных операций и синхронизация высокого уровня
   (5.3.6–5.3.7)** — как атомарные операции упорядочивают обычные данные;
   где гарантии мьютексов/фьючерсов.

8. **Типичные ошибки** — misuse relaxed, забытый acquire, двойной `get`,
   надежда на неатомарную переменную, переупорядочение.

9. **Шпаргалка** — таблица примитивов и упорядочений.
