# Решение 3.5

## transfer

```cpp
void transfer(Account& from, Account& to, int amount) {
    std::lock(from.m_, to.m_);                                // оба разом, без deadlock
    std::lock_guard<std::mutex> g1(from.m_, std::adopt_lock); // владеет уже захваченным
    std::lock_guard<std::mutex> g2(to.m_, std::adopt_lock);   // владеет уже захваченным
    from.balance_ -= amount;
    to.balance_ += amount;
}
```

Разбор:

- **`std::lock(from.m_, to.m_)`** — захватывает оба мьютекса «атомарно»:
  если какой-то из них недоступен, освобождает уже захваченные и ждёт весь
  набор целиком. Поток никогда не остаётся с одним мьютексом, ожидая второй, —
  поэтому цикл ожидания невозможен и порядок `from`/`to` не важен.
- **`std::lock_guard` с `std::adopt_lock`** — флаг говорит обёртке: мьютекс
  уже захвачен, осталось только корректно его освободить. Без `adopt_lock`
  обёртка попыталась бы заблокировать мьютекс повторно — тот же поток упёрся
  бы в себя (зависание, для нерекурсивного мьютекса это UB).
- Деструкторы `g1`/`g2` разблокируют оба мьютекса при любом исходе, в том
  числе при исключении между строками.

## main

```cpp
std::vector<std::thread> threads;
for (int t = 0; t < 4; ++t) {
    threads.emplace_back([&a, &b, t] {
        for (int i = 0; i < 1000; ++i) {
            if ((i + t) % 2 == 0) transfer(a, b, (i % 20) + 1);
            else                  transfer(b, a, (i % 20) + 1);
        }
    });
}
for (auto& t : threads) t.join();
```

Чередование направления гарантирует, что потоки пробуют обе
последовательности блокировки — и `std::lock` справляется с любой.

## Почему итог всегда 100000

Перевод лишь переносит сумму между счетами; суммарный баланс инвариантен.
Если бы пара обновлений потерялась (гонка) или перевод завис (deadlock),
итог отличался бы или программа не завершилась бы.
