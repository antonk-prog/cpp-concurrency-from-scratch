# Лаба 3.7. Два потокобезопасных синглтона
Модуль: 3. Совместное использование данных несколькими потоками
Тип: напиши с нуля

## Мотивация

Конфигурация приложения, пул соединений, логгер — такие объекты нужны в одном
экземпляре, создаваемом лениво при первом обращении. Но «создать один раз»
легко написать неправильно: без синхронизации два потока могут создать два
экземпляра или прочитать недоинициализированный объект. Нужен потокобезопасный
ленивый синглтон.

## Задача

Напиши класс `Singleton` и **два разных** потокобезопасных синглтона:

1. **Через `std::call_once` и `std::once_flag`.** Геттер хранит объект
   (например, в `static std::shared_ptr<Singleton>`), а инициализацию выполняет
   `std::call_once(flag, ...)` — ровно один раз, остальные потоки ждут.
2. **Через `static`-локальную переменную.** Геттер объявляет
   `static Singleton s;` и возвращает `s`. Инициализация статической локальной
   переменной в C++11 и новее потокобезопасна.

Класс `Singleton`: добавь `static int instances;`, который **увеличивается
в конструкторе** — по числу созданных экземпляров.

Больше ничего писать не нужно — `main` не требуется.

## Требования

1. Код компилируется без ошибок и предупреждений:
   `g++ -std=c++17 -pthread -Wall -Wextra -c main.cpp -o /tmp/lab_03_07.o`.
2. Ровно два геттера: один на `std::call_once`, другой на `static`-локальной
   переменной. Нет прямого создания `Singleton` вручную.
3. В синглтонах нет никакого мьютекса — синхронизацию обеспечивают `call_once`
   и `static`-локальная переменная.
4. Код корректен под сценарием «8 потоков по 1000 обращений к каждому
   геттеру»: каждый синглтон создан ровно один раз (проверяется в CI
   с тестовым `main`).
