# Лаба 3.7. Два потокобезопасных синглтона — средняя
Модуль: 3. Совместное использование данных несколькими потоками
Тип: напиши с нуля

## Мотивация

Конфигурация приложения, пул соединений, логгер — такие объекты нужны в одном
экземпляре, создаваемом лениво при первом обращении. Но «создать один раз»
легко написать неправильно: без синхронизации два потока могут создать два
экземпляра или прочитать недоинициализированный объект. Нужен потокобезопасный
ленивый синглтон.

## Задача

Напиши класс `Singleton` и **два разных** потокобезопасных синглтона:

1. **Через `std::call_once` и `std::once_flag`.** Геттер хранит объект
   (например, в `static std::shared_ptr<Singleton>`), а инициализацию выполняет
   `std::call_once(flag, ...)` — ровно один раз, остальные потоки ждут.
2. **Через `static`-локальную переменную.** Геттер объявляет
   `static Singleton s;` и возвращает `s`. Инициализация статической локальной
   переменной в C++11 и новее потокобезопасна.

Класс `Singleton`: добавь `static int instances;`, который **увеличивается
в конструкторе** — по числу созданных экземпляров.

В `main`:

1. Получи ссылки/указатели на оба синглтона до запуска потоков (зафиксируй
   эталоны).
2. Запусти **8 потоков**: каждый 1000 раз вызывает оба геттера и проверяет,
   что каждый геттер возвращает один и тот же экземпляр (совпадает
   со своим эталоном).
3. После `join()` всех проверь: `Singleton::instances == 2` (каждый синглтон
   создан ровно один раз).
4. Выведи `All checks passed` (при любой ошибке — сообщение и код возврата 1).

## Требования

1. Сборка без ошибок и предупреждений:
   `g++ -std=c++17 -pthread -Wall -Wextra main.cpp -o /tmp/lab_03_07`.
2. Ровно два геттера: один на `std::call_once`, другой на `static`-локальной
   переменной. В `main` нет прямого создания `Singleton` вручную.
3. В `main` нет никакого мьютекса — синхронизацию обеспечивают `call_once`
   и `static`; для общего флага/счётчика проверок используй атомарный тип.
4. Ровно 8 потоков по 1000 обращений к каждому геттеру, все `join()`-ятся.
5. Вывод `All checks passed` — всегда, на любом числе ядер. Программа чиста
   под ThreadSanitizer.

Каркас в `starter/main.cpp` (компилируется). Собери:

## Чеклист самопроверки

- [ ] Компилируется с `-Wall -Wextra` без замечаний.
- [ ] Оба геттера возвращают один и тот же экземпляр во всех потоках.
- [ ] `Singleton::instances == 2` после завершения всех потоков.
- [ ] Прогнал под ThreadSanitizer — гонок нет.
