# Грабли 3.7

## Пишешь «double-checked locking» вручную

Проверить указатель, потом взять мьютекс, потом проверить снова — классическая
ошибка: первое чтение без синхронизации — data race. Не изобретай — есть
`std::call_once` и `static`.

## Путаешь `once_flag` и сам вызов

`once_flag` — метка состояния («инициализация уже выполнена?»). Без неё
`call_once` не имеет где хранить факт выполнения. Метка должна быть одна
на геттер; `static` внутри функции — правильное место.

## Проверяешь `instances == 1` вместо `== 2`

Ты создаёшь ДВА синглтона (call_once и static) — итого два экземпляра. Один
экземпляр значил бы, что один из геттеров либо не создал объект, либо создал
его несколько раз.

## Используешь обычный `bool` для общего флага

Несколько потоков пишут флаг ошибки — это data race. Возьми `std::atomic<bool>`.

## Сравниваешь экземпляры разных синглтонов

`get_singleton_call_once()` и `get_singleton_static()` — два РАЗНЫХ объекта.
Сравнивай адрес каждого геттера с его же эталоном, а не между собой.
