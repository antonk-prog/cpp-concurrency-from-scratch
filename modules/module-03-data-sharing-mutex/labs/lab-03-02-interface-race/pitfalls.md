# Грабли 3.2

## top() возвращает ссылку

`T& top()` выпускает ссылку на защищённые данные за пределы блокировки.
После снятия мьютекса другой поток может модифицировать стек (push → перераспределение),
и чтение по ссылке становится data race / UB. Это нарушение правила «не выпускай
ссылки за пределы блокировки» — см. лекцию модуля 3.

## Раздельные top() и pop()

Даже если оба метода по отдельности защищены мьютексом, интерфейс из двух
вызовов создаёт гонку: между `top()` и `pop()` другой поток может изменить стек.
Два потока могут взять один и тот же элемент или потерять один из них.
Решение — единый `pop()`, который читает и удаляет под одной блокировкой.

## Возвращаю значение из pop() по значению, а не через shared_ptr

`T pop()` возвращает копию из-под блокировки. Если копирование бросит
исключение (например, `std::bad_alloc` у `std::vector`), элемент уже удалён из
стека, а к вызывающему значение не попало — данные потеряны (проблема Каргилла).
`std::shared_ptr<T>` копируется без исключений — надёжно.

## Считаю, что empty() делает интерфейс безопасным

`if (!st.empty()) { auto v = st.pop(); }` — всё ещё гонка: между `empty()` и
`pop()` стек может опустеть. Поэтому `pop()` сам бросает `empty_stack`.
`empty()` остаётся лишь подсказкой, а не гарантией.

## Не ловлю empty_stack в циклах

Поток-читатель должен обрабатывать `empty_stack` как сигнал «стек опустел».
Если писать `while (!st.empty())`, гонка между empty и pop останется. Цикл
строится на `try { pop() } catch (empty_stack&) { break; }`.
