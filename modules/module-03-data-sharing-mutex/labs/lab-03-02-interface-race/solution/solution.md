# Решение 3.2

## В чём баг

В стартовом коде два дефекта, оба — следствие плохого интерфейса:

1. **Утечка ссылки за пределы блокировки.** `T& top()` возвращает ссылку на
   элемент, который находится под мьютексом. Как только `top()` завершился,
   мьютекс снят, а поток продолжает читать по этой ссылке. Другой поток в это
   время может сделать `push()` (который способен перераспределить внутренний
   контейнер), и чтение по висячей ссылке становится data race / UB. Это
   нарушение правила «никогда не выпускать ссылки на защищённые данные за
   пределы блокировки» — подробно в лекции модуля 3.

2. **Интерфейсная гонка top()+pop().** Даже если `top()` возвращает копию,
   между `top()` и `pop()` другой поток может изменить стек. Классический пример
   из лекции модуля 3 (раздел «Интерфейсные гонки»): два потока могут оба
   прочитать верхний элемент и «потерять» один из них.

## Как чиним — единая операция pop()

```cpp
std::shared_ptr<T> pop() {
    std::lock_guard<std::mutex> guard(m_);
    if (data_.empty()) throw empty_stack();
    auto res = std::make_shared<T>(data_.top());
    data_.pop();
    return res;
}
```

- Чтение верхнего элемента и его удаление — **один неделимый шаг** под одной
  блокировкой. Гонка top/pop исчезает, потому что раздельных вызовов больше нет.
- Возврат через `std::shared_ptr<T>` (вариант из лекции модуля 3): указатель
  можно копировать без исключений, поэтому даже при нехватке памяти элемент не
  «теряется» в момент удаления (проблема Каргилла, разобрана в лекции). Из-под
  блокировки наружу выходит только копия значения — никакой ссылки на внутренние
  данные.
- Пустой стек — исключение `empty_stack`, а не UB. Это безопасно даже если
  между проверкой и извлечением стек опустел.

## main

Каждый поток в цикле извлекает `pop()`, ловит `empty_stack` (когда стек
опустел) и копит сумму. После `join()` всех потоков сумма должна совпасть
с `1 + 2 + ... + N`. Так как элементы уникальны, любая потеря или дубликат
сразу изменят сумму.
