# Лаба 3.3. Обмен без deadlock
Модуль: 3. Совместное использование данных несколькими потоками
Тип: допиши TODO

## Мотивация

Операции, которым нужны два объекта (обмен, сравнение, перемещение между
контейнерами), требуют блокировки двух мьютексов. Если потоки блокируют их
в разном порядке, возникает взаимная блокировка (deadlock): каждый держит один
мьютекс и ждёт второй — ни один не движется. Классическое решение — блокировать
оба мьютекса одновременно через `std::lock` / `std::scoped_lock`.

## Задача

Дан класс `X` с внутренними данными `some_big_object detail_` и мьютексом `m_`.
Функция `swap(X&, X&)` должна обменять содержимое двух объектов.

В стартовом коде `swap` реализован **неправильно**: блокирует `lhs.m_` и `rhs.m_`
по отдельности. Два потока, вызывающие `swap` с переставленными аргументами
(`swap(a, b)` в одном и `swap(b, a)` в другом), заблокируют мьютексы в разном
порядке и намертво зависнут (deadlock).

Твоя задача — дописать TODO:

1. В `swap` замени две раздельные блокировки на одновременную через
   `std::scoped_lock` (C++17): `std::scoped_lock guard(lhs.m_, rhs.m_);`.
   Это тот же алгоритм, что и `std::lock`, но с RAII — мьютексы гарантированно
   разблокируются в деструкторе, даже при исключениях.

В `main` ничего дописывать не нужно: там уже есть сценарий с двумя потоками,
которые многократно вызывают `swap` с переставленными аргументами
(`swap(a, b)` и `swap(b, a)`). В «плохой» версии он приводит к deadlock,
в исправленной — программа завершается корректно.

## Требования

1. Сборка без ошибок и предупреждений:
   `g++ -std=c++17 -pthread -Wall -Wextra main.cpp -o /tmp/lab_03_03`.
2. `swap` использует `std::scoped_lock` для одновременной блокировки обоих
   мьютексов (никаких двух раздельных `lock_guard`).
3. Проверка `&lhs == &rhs` остаётся: блокировать один и тот же мьютекс дважды —
   UB.
4. Программа с двумя потоками, делающими swap с переставленными аргументами,
   завершается корректно (не зависает) и возвращает 0.
