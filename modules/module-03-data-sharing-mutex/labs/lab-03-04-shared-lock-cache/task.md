# Лаба 3.4. DNS-кэш с общим доступом — средняя
Модуль: 3. Совместное использование данных несколькими потоками
Тип: напиши с нуля

## Мотивация

Кэш DNS-записей читается при каждом запросе (много читателей), а обновляется
редко (администратор добавил запись). Обычный `std::mutex` заставил бы читателей
ждать друг друга, хотя они друг другу не мешают. `std::shared_mutex` позволяет
читать параллельно, оставляя запись монопольной.

## Задача

Напиши потокобезопасный класс `dns_cache`:

- приватные поля: `std::map<std::string, std::string> entries_` и
  `mutable std::shared_mutex m_`;
- `std::string find(const std::string& name) const` — возвращает запись,
  а если её нет — пустую строку. Использует `std::shared_lock` (общая
  блокировка, читатели не мешают друг другу);
- `void update(const std::string& name, const std::string& entry)` — кладёт
  запись в кэш. Использует `std::lock_guard<std::shared_mutex>` (монопольная
  блокировка, один писатель).

В `main`:

1. Предзагрузи базовые записи (см. формулы ниже).
2. Запусти **4 потока-читателя**: каждый 1000 раз читает запись по
   детерминированной формуле и проверяет: если запись найдена, её значение
   обязано совпадать с ожидаемым.
3. Параллельно запусти **2 потока-писателя**: каждый добавляет 500 записей
   по формуле ниже.
4. Дождись всех потоков через `join()`, проверь, что все записанные ключи
   на месте с правильными значениями.
5. Выведи `All checks passed` (при любой несовпадающей записи — сообщение
   об ошибке и код возврата 1).

Формулы:

- базовые записи: `www.example.com` → `10.0.0.1`, `api.example.com` →
  `10.0.0.2`, `mail.example.com` → `10.0.0.3`;
- писатель `w` (0 или 1), ключ `i` (0..499): имя `host` + `w*500+i`,
  значение `10.0.1.` + `w*100+i`;
- читатель: на чётной итерации `i` берёт базовый ключ с индексом
  `(i/2) % 3`; на нечётной — ключ писателя `w = i % 2`, `k = (i/2) % 500`.

## Требования

1. Сборка без ошибок и предупреждений:
   `g++ -std=c++17 -pthread -Wall -Wextra main.cpp -o /tmp/lab_03_04`.
2. Класс `dns_cache` содержит данные и мьютекс; `find` — через
   `std::shared_lock`, `update` — через `std::lock_guard` (монопольная
   блокировка).
3. Никаких прямых `lock()`/`unlock()`; никакого `std::mutex` вместо
   `std::shared_mutex`.
4. Ровно 4 читателя и 2 писателя с указанными объёмами, все `join()`-ятся.
5. Вывод `All checks passed` — всегда, на любом числе ядер. Программа чиста
   под ThreadSanitizer.
