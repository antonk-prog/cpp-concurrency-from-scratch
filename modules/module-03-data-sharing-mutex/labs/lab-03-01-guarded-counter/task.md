# Лаба 3.1. Защищённый счётчик — базовая
Модуль: 3. Совместное использование данных несколькими потоками
Тип: напиши с нуля

## Мотивация

Счётчик посещений, статистика запросов, прогресс-бары — классические случаи
общего изменяемого состояния, которое несколько потоков инкрементят одновременно.
Без синхронизации это data race: инкремент `++x` не атомарен (читать → прибавить →
записать), и потоки могут потерять обновления. Защита счётчика мьютексом —
первый шаг к честному разделяемому состоянию.

## Задача

Напиши класс `Counter` с одним `int value_` и `std::mutex m_`:

- `void increment()` — под `std::lock_guard` увеличивает `value_` на 1;
- `int get() const` — под `std::lock_guard` возвращает текущее значение.

Данные и мьютекс — в одном классе (приватные поля). Методы, трогающие данные,
блокируют мьютекс. Не используй `lock()`/`unlock()` напрямую — только RAII.

В `main` создай `Counter`, запусти **4 потока**, каждый делает `increment()`
ровно `ITERATIONS = 100'000` раз, дождись их через `join()`, затем выведи
`counter.get()`. Результат должен быть ровно `4 * 100'000 = 400'000`.

Ожидаемый вывод:

```
Final counter: 400000
```

## Требования

1. Сборка без ошибок и предупреждений:
   `g++ -std=c++17 -pthread -Wall -Wextra main.cpp -o /tmp/lab_03_01`.
2. Класс `Counter`: приватные `int value_` и `std::mutex m_`; методы
   `increment()` и `get() const` блокируют мьютекс через `std::lock_guard`.
3. Никаких прямых `lock()`/`unlock()`.
4. Ровно 4 потока по 100 000 инкрементов, все `join()`-ятся.
5. Вывод `Final counter: 400000` — всегда, на любом числе ядер.

## Стартовый код

Стартового кода нет — пиши с нуля в файле `main.cpp`. Собери:

```
g++ -std=c++17 -pthread -Wall -Wextra main.cpp -o /tmp/lab_03_01
```

## Чеклист самопроверки

- [ ] Программа компилируется с `-Wall -Wextra` без замечаний.
- [ ] Класс `Counter` содержит и данные, и мьютекс; все методы используют
      `std::lock_guard`.
- [ ] Результат всегда 400000, независимо от запуска.
- [ ] Запустил несколько раз подряд — результат не меняется.
