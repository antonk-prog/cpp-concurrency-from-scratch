# Лаба 3.6. Слияние результатов с отложенной блокировкой

Тип: допиши TODO

## Мотивация

Поток часто работает так: что-то посчитал локально (без общего состояния),
затем коротко обновил общие данные и снова продолжил локальную работу.
Держать мьютекс всю локальную фазу — значит зря блокировать других.
`std::unique_lock` с флагом `std::defer_lock` позволяет создать объект
блокировки заранее, а взять её только на время слияния.

## Задача

В стартовом коде воркер копит локальную сумму и сливает её в общий
`shared_total`. Допиши два места (TODO):

1. Создай `std::unique_lock<std::mutex> lk(m, std::defer_lock)` **до** локальной
   работы — мьютекс при этом ещё не заблокирован.
2. После локальной работы вызови `lk.lock()`, прибавь `local` к `shared_total`
   и сразу `lk.unlock()` — блокировка держится только на время слияния.

Больше ничего писать не нужно — `main` не требуется.

1. Код компилируется без ошибок и предупреждений:
   `g++ -std=c++17 -pthread -Wall -Wextra -c main.cpp -o /tmp/lab_03_06.o`.
2. `unique_lock` создаётся с `std::defer_lock`; блокировка берётся и снимается
   явными `lock()`/`unlock()` через объект `unique_lock`.
3. Никаких `lock_guard` в воркере; никаких `sleep`.
4. Код корректен под сценарием «`kWorkers = 4` потока по `kIterations = 2000`
   итераций»: итог сохраняется (проверяется в CI с тестовым `main`).
