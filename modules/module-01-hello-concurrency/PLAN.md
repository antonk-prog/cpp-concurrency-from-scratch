# Модуль 1 — Здравствуй, мир конкурентности в C++! — ПЛАН

## Допущения модуля

### Прогрессия (что разрешено)
Только примитивы модуля 1: `std::thread`, `std::this_thread::get_id()`, `join()`, `detach()`.
Запрещено всё из более поздних модулей: мьютексы (гл. 3), условные переменные (гл. 4),
атомарные типы (гл. 5). Синхронизации общей памяти пока НЕТ.

### Последствие для лаб
Поскольку синхронизация отсутствует, задачи модуля строятся на **независимых** задачах
в потоках: каждый поток делает своё, не трогая общий изменяемый вывод (или пишет в свой
приватный буфер). Общий `std::cout` между потоками — вне модуля (гонка, гл. 3).

### Список лаб (тип, название, суть, чему учит)

1. **lab-01-01-run-two-tasks (допиши TODO, базовая)**
   - Суть: в стартовом коде дописать запуск 2 потоков с независимыми вычислениями
     и `join()`, результаты собрать через приватные переменные, переданные по ссылке.
   - Чему учит: как запустить поток с функцией, что `join()` обязателен, поток —
     это исполнение отдельной функции.

2. **lab-01-02-predict-detach (предскажи вывод, базовая)**
   - Суть: дан код с `detach()` без `join()`; предсказать, что выведет программа
     и почему это недетерминировано / рискованно (главный поток может завершиться
     раньше фонового; вывод не гарантирован).
   - Чему учит: разница join/detach, чем опасен detach, состояние гонки по времени.

3. **lab-01-03-fix-unjoined (найди и почини, средняя)**
   - Суть: стартовый код запускает поток, но при исключении в main поток не join-ится
     → `std::terminate`. Надо починить (RAII-обёртка / try-catch), не меняя логику.
   - Чему учит: обязательность join/detach до разрушения `std::thread`, безопасность
     при исключениях (прообраз RAII-обёрток главы 2).

> Студент пока не знает RAII-обёрток мьютексов (гл. 3), но в этой лабе чиним именно
> обязательность join/detach — тема самой главы 1. Обёртка `thread_guard` — свой код,
> не C++20 API.

## Заголовки лекции (README.md) с 1–2 фразами содержания

1. **Зачем это нужно** — что такое конкурентность и многопоточность, зачем: разделение
   неотложных задач и повышение производительности (параллелизм задач и данных);
   когда не нужна (издержки запуска потоков, ограниченность ресурса).

2. **Как это работает** — подходы: несколько процессов vs несколько потоков; общее
   адресное пространство потоков; почему книга про потоки, а не процессы.

3. **Минимальные примеры** — Hello World в один поток и `Hello Concurrent World`
   с `std::thread` + `join()`; запуск потока с функцией; обязательность join/detach;
   `std::this_thread::get_id()`.

4. **Типичные ошибки** — забыл `join()`/`detach()` → `std::terminate`; «гонка» за вывод
   (здесь просто предупреждение, что общий вывод между потоками — позже, гл. 3);
   ожидание, что порядок вывода детерминирован.

5. **Шпаргалка** — таблица: конструктор `std::thread`, `join`, `detach`, `get_id`,
   `hardware_concurrency` (указать, что подробности — гл. 2).
