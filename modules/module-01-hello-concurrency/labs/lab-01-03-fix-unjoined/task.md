# Лаба 1.3. Почини потерянный join
Модуль: 1. Здравствуй, мир конкурентности в C++!
Тип: найди и почини

## Мотивация

Программа обрабатывает пакет данных: рабочий поток выполняет тяжёлые вычисления,
а главный ждёт его через `join()`. Проблема в том, что главный поток перед
`join()` может бросить исключение (например, при чтении файла или проверке
входных данных). Если `join()` так и не будет вызван, `std::thread` окажется
уничтожен в состоянии «всё ещё запущен» — и программа упадёт через
`std::terminate()`. Нужно сделать так, чтобы поток всегда дожидались,
даже при исключении.

## Задача

Дан стартовый код. Найди в нём заложенный баг и почини его так, чтобы
выполнение было безопасным:

1. Обработка данных (`doWork`) запускается в отдельном потоке.
2. Между запуском потока и `join()` возможен бросок исключения (в `main` это
   имитирует проверка, которая бросает `std::runtime_error`, когда входной
   параметр неверен).
3. Сейчас при броске исключения `join()` пропускается, и программа аварийно
   завершается (сработает `std::terminate()`).

Твоя задача — переписать код так, чтобы:

- рабочий поток **всегда** дожидались через `join()` — как в нормальном пути,
  так и при исключении;
- логика обработки не изменилась;
- не использовать `detach()`.

Проверь себя: с неверным параметром (исключение брошено) программа должна
**аккуратно** напечатать сообщение об ошибке и завершиться корректно,
а не упасть с аварийным сообщением про `terminate`.

## Требования

1. Сборка без ошибок и предупреждений:
   `g++ -std=c++17 -pthread -Wall -Wextra main.cpp -o /tmp/lab_01_03`.
2. Рабочий поток всегда дожидается через `join()` — в том числе при исключении.
3. Не используется `detach()`.
4. Программа с корректным параметром печатает результат работы.
5. Программа с некорректным параметром не падает аварийно, а завершается
   с сообщением об ошибке.

## Стартовый код

Один файл `main.cpp`. Собери и запусти с параметром:

```
g++ -std=c++17 -pthread -Wall -Wextra main.cpp -o /tmp/lab_01_03
/tmp/lab_01_03 42        # корректный параметр
/tmp/lab_01_03 -1        # некорректный — сейчас падает аварийно
```
