# Грабли 1.1

## Забыл обернуть ссылку в `std::ref`

Конструктор `std::thread` копирует аргументы. Если передать `sum` напрямую,
поток получит копию, функция запишет результат в копию, а `sum` в `main`
останется нулём. Ссылка нужна только через `std::ref(sum)`.

### Почему именно `std::ref`

Внутри конструктор `std::thread` не вызывает твою функцию сразу и не «помнит»
переданную ссылку как ссылку. Вместо этого он **копирует** каждый аргумент
(через `std::decay_t`, т.е. снимает ссылочность) и хранит копии. Уже потом,
когда поток стартует, эти копии передаются в целевую функцию.

Из-за этого если ты пишешь:

```cpp
int sum = 0;
std::thread t(computeSum, n, sum);   // sum передаётся ПО ЗНАЧЕНИЮ (копия)
```

то поток вызывает `computeSum(n, копия_sum)`. Внутри `computeSum` параметр
`int& sum` связывается с **копией**, функция пишет в копию, а настоящая `sum`
в `main` так и остаётся `0`.

`std::ref(sum)` решает это: он возвращает объект `std::reference_wrapper<int>`,
который внутри хранит ссылку на `sum`. `std::reference_wrapper` — это
«носитель ссылки», который можно копировать и хранить, не теряя связь
с оригиналом. Когда поток наконец вызывает `computeSum`, обёртка разворачивается
обратно в настоящую ссылку на `sum`, и функция пишет в нужную переменную:

```cpp
std::thread t(computeSum, n, std::ref(sum));  // sum передаётся ПО ССЫЛКЕ
```

Коротко: `std::thread` хранит аргументы по значению; `std::ref` позволяет
«протащить» через это копирование настоящую ссылку на внешнюю переменную.

## Прочитал результат до `join()`

Если печатать `sum`/`count` до `join()`, поток может ещё не закончить запись —
получишь 0 или частичный результат. Правильно: сначала оба `join()`, потом печать.

## Передал `n` по ссылке — не нужно

`n` поток не меняет, его можно (и нужно) передавать по значению. Копирование
`int` дёшево и не создаёт лишних связей между потоками.

## Запустил только один поток

В задаче два независимых вычисления — должны быть и два `std::thread`. Если
запустить один, второй вызов выполнится последовательно в `main`, что ломает
смысл упражнения (должна быть реальная конкурентность двух задач).
