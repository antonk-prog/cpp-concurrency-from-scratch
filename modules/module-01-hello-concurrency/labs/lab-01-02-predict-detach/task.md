# Лаба 1.2. Предскажи вывод detach — базовая
Модуль: 1. Здравствуй, мир конкурентности в C++!
Тип: предскажи вывод

## Мотивация

Фоновые задачи (проверка обновлений, запись логов) часто запускают в отсоединённом
потоке через `detach()`, не дожидаясь его. Но у `detach()` есть коварная особенность:
после отсоединения поток живёт сам по себе, и его судьба перестаёт быть связана
с главным потоком. Понимать, что в этом случае происходит с выводом, — значит
понимать саму природу конкурентности и не полагаться на «случайно повезло».

## Задача

Изучи приведённую ниже программу и ответь письменно:

1. **Что напечатает программа?** Запиши все возможные варианты вывода,
   которые реально могут получиться при запуске.
2. **Почему результат недетерминирован?** Объясни, от чего зависит, что именно
   увидит пользователь.
3. **Корректна ли программа** с точки зрения времени жизни потока? Укажи,
   есть ли здесь неопределённое поведение (UB) или это просто непредсказуемый
   вывод.

```cpp
#include <iostream>
#include <thread>

void background() {
    std::cout << "Фоновая задача отработала\n";
}

int main() {
    std::thread t(background);
    t.detach();
    std::cout << "Главный поток завершается\n";
    return 0;
}
```

Не запускай программу вручную, чтобы подсмотреть ответ, — сначала напиши свои
рассуждения. Запуск (несколько раз) — лишь проверка твоих предсказаний.

## Требования

1. Дан полный список возможных вариантов вывода, которые реально могут
   получиться при запуске.
2. Объяснено, от чего зависит, какой именно вариант увидит пользователь.
3. Описана судьба фонового потока и главного потока после `detach()`.
4. Сделан обоснованный вывод о том, есть ли здесь неопределённое поведение (UB)
   или вывод просто непредсказуем — с аргументацией, а не голословно.
