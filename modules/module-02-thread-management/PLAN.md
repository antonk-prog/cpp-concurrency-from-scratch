# Модуль 2 — Управление потоками — ПЛАН

## Допущения модуля

### Прогрессия (что разрешено)
Примитивы модуля 2 (всё из главы 2):
- `std::thread`: конструктор с вызываемым объектом и аргументами, `join()`,
  `detach()`, `joinable()`, `get_id()`, перемещение (`std::move`), контейнеры
  `std::vector<std::thread>`.
- Передача аргументов: по значению (копия), `std::ref` для ссылок,
  `std::move` для move-only (напр. `std::unique_ptr`).
- RAII-обёртки: `thread_guard` (join в деструкторе), `scoped_thread`
  (владеет потоком, join в деструкторе).
- `std::this_thread::get_id()`, `std::thread::id`, сравнение/хэш id.
- `std::thread::hardware_concurrency()`.
- `std::accumulate` для задачи про parallel_accumulate (алгоритм не цель,
  а средство демонстрации разбиения работы).

Запрещено (позднее): мьютексы (гл. 3), условные переменные/фьючерсы (гл. 4),
атомики (гл. 5).

### Последствие для лаб
Разделяемый изменяемый вывод/данные без синхронизации — вне модуля (гонка, гл. 3).
Потоки пишут в собственные приватные результаты; главный поток собирает их после
`join()`. Исключение: пример с `std::cout` для вывода id (демонстрация, безопасна
при одном потоке-писателе или в учебном контексте, о чём честно оговариваем).

## Заголовки лекции (README.md) с 1–2 фразами содержания

1. **Зачем это нужно** — как запустить поток и передать ему задачу; зачем
   управлять временем жизни потока (join/detach), передавать аргументы и владение.

2. **Как это работает** — конструктор `std::thread`; копирование аргументов
   в хранилище потока; rvalue-передача при вызове (отсюда `std::ref`/`std::move`);
   RAII-обёртки (`thread_guard`, `scoped_thread`) как гарантия `join()`.

3. **Минимальные примеры** — запуск с функцией/функтором/лямбдой; `join()`/`detach()`
   и их обязательность; передача аргументов (`std::ref`, `std::move`);
   перемещение владения потоком; возврат `std::thread` из функции.

4. **Типичные ошибки** — «самый неприятный случай синтаксического анализа»
   (`std::thread t(background_task());`); забыл `join()`/`detach()` → `terminate`;
   ссылка на локальную переменную в detached-потоке → UB; передал ссылку без
   `std::ref`; скопировал `std::thread` вместо перемещения.

5. **Шпаргалка** — таблица: запуск, join/detach/joinable, передача аргументов,
   std::ref/std::move, get_id/this_thread::get_id, hardware_concurrency,
   thread_guard/scoped_thread.
