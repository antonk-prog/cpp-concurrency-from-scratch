# Грабли 2.2

## Сделал `scoped_thread` с `std::thread&` (как thread_guard)

Тогда обёртка не владеет потоком — а в этом вся суть упражнения. Поток должен
храниться в классе по значению (`std::thread t;`), чтобы обёртка была
единственным владельцем.

## Забыл удалить копирование

Если конструктор копирования не удалён, компилятор сгенерирует его, а две
копии обёртки попытаются `join()` один поток. Копирование обязательно
`= delete`.

## Не передал владение в конструктор (без std::move)

`scoped_thread st(worker);` где `worker` — именованный `std::thread`, не
скомпилируется без `std::move` (копирование удалено). Либо `std::move(worker)`,
либо временный объект: `scoped_thread st(std::thread(doWork, 7));`.

## Деструктор без проверки joinable()

`join()` у уже завершённого/отсоединённого потока — ошибка. Всегда проверяй
`t.joinable()` перед `join()`.

## Думаешь, что после return std::thread нужен явный std::move

Временный объект (`return std::thread(...)`) перемещается сам, явный `std::move`
не нужен и даже мешает. `std::move` требуется только для именованных объектов.

## Вызвал join() в main И в деструкторе

Если отдельно позвать `st`-потока нельзя — поток спрятан в обёртке. Лишний
`join()` по сохранённой ссылке снова привёл бы к ошибке. Полагайся на
деструктор.
