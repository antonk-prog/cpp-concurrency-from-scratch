# Решение лабы 7.1

## Реализация

**push()** — CAS-цикл:

```cpp
void push(T const& data) {
    node* const new_node = new node(data);
    new_node->next = head.load();
    while (!head.compare_exchange_weak(new_node->next, new_node)) {}
}
```

Узел создаётся и полностью готовится **до** публикации в `head`: после того
как `head` укажет на него, другой поток сможет его прочитать, поэтому менять
его нельзя. `compare_exchange_weak` атомарно проверяет, что `head` не изменился
с момента чтения; если изменился — первый аргумент (`new_node->next`) обновляется
актуальным `head`, и цикл повторяется.

**pop()** — CAS-цикл с защитой от двойного извлечения:

```cpp
std::shared_ptr<T> pop() {
    node* old_head = head.load();
    while (old_head &&
           !head.compare_exchange_weak(old_head, old_head->next)) {}
    return old_head ? old_head->data : std::shared_ptr<T>();
}
```

CAS по `head` гарантирует, что конкретный узел извлечёт ровно один поток:
если два потока прочитали один и тот же `head`, у второго CAS провалится
(значение уже изменено), он перечитает `head` и попробует следующий узел.

## Почему shared_ptr для данных

В главе 3 мы видели: возврат значения по ссылке в `pop()` небезопасен при
исключении (копирование может бросить, и значение потеряется, а узел уже
извлечён). Здесь данные хранятся в `std::shared_ptr<T>`, а `pop()` возвращает
`shared_ptr` — операция не бросает, значение не теряется. Распределение памяти
под данные происходит в `push()` (там всё равно выделяется узел).

## Про «утечку узлов»

Извлечённые узлы не удаляются (`delete` нет) — это осознанное упрощение.
Если удалить узел сразу после извлечения, другой поток, который ещё держит
указатель на него (прочитал `old_head`, но не успел выполнить CAS), разыменует
висячий указатель — UB. Управление памятью (подсчёт потоков, указатели
опасности, подсчёт ссылок) — тема следующих разделов лекции.
