# Грабли лабы 7.1

## CAS-цикл без обновления `expected`

Первый аргумент `compare_exchange_weak` при неудаче автоматически обновляется
текущим значением. Если использовать новое значение в следующей попытке —
цикл корректен; если перезагружать `head` вручную или заново читать — можно
пропустить изменения других потоков.

## Опубликовал узел до его готовности

После того как `head` укажет на узел, другие потоки начнут его читать —
менять его нельзя. Узел (данные и `next`) обязан быть полностью готовым
до CAS.

## В `pop()` не проверил `old_head != nullptr`

Если стек пуст (`head == nullptr`), выражение `old_head->next` в цикле —
разыменование nullptr, UB. Проверяй `old_head` в условии цикла.

## Извлёк узел без CAS

Если `pop()` просто читает `head` и присваивает `head = old_head->next`
без CAS — два потока извлекут один узел (дубликат). CAS обязателен.

## Удалил узел сразу после извлечения

В этой лабе удалять узлы нельзя: другой поток может ещё держать указатель
на извлечённый узел (прочитал `old_head`, не успел CAS) — разыменование
висячего указателя, UB. Управление памятью — отдельная тема; здесь утечка
осознанна.

## Вернул значение по ссылке / по значению с копированием

Если копирование данных бросает исключение, значение теряется (узел уже
извлечён). Используй `std::shared_ptr<T>` — копирование `shared_ptr` не бросает.

## Проверял «по поведению» без TSan

Логические гонки lock-free кода коварны. Прогони `-fsanitize=thread`; также
полезен стресс-прогон (много потоков, много итераций) и проверка уникальности
извлечённых значений.
