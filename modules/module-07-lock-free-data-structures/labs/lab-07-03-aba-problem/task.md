# Лаба 7.3. Проблема ABA в lock-free стеке — сложная
Модуль: 7. Конкурентные структуры данных без блокировок
Тип: предскажи вывод

## Мотивация

Операция сравнения-обмена (CAS) сравнивает **значения**, а не объекты: если
указатель «вернулся» к прежнему адресу, CAS посчитает его неизменным, хотя
это может быть совершенно другой объект. Когда структура переиспользует память
(например, возвращает извлечённые узлы в пул и вставляет их снова), этот эффект
превращается в классическую **проблему ABA** — одну из главных ловушек
lock-free алгоритмов.

## Задача

В стартовом коде lock-free стек, который **переиспользует узлы**: извлечённые
узлы возвращаются в пул (`free_list`), а новые вставки берут узлы из пула,
если он не пуст. Это экономит распределение памяти, но создаёт риск ABA.

Предскажи и объясни:

1. Какое неверное поведение возможно в этом коде (при какой последовательности
   событий)?
2. Почему CAS «не замечает» проблему (что именно сравнивается)?
3. К чему приводит проблема на практике (потеря данных? порча структуры?
   неопределённое поведение?) — и почему это недетерминировано.
4. Как защититься (предложи минимум один механизм).

## Требования

1. Опиши сценарий ABA по шагам (поток 1 читает A → приостанавливается →
   поток 2 … → поток 1 возобновляется и делает CAS).
2. Объясни, почему CAS успешен, хотя «то же значение» — это другой объект.
3. Честно укажи, является ли результат неопределённым поведением или просто
   логической ошибкой (не выдумывай детерминированный вывод).
4. Предложи защиту: счётчик ABA (версия в атомарной структуре «указатель +
   счётчик») или иной механизм из лекции.
5. Код решения (защищённая версия) компилируется без предупреждений.

## Стартовый код

Файлы: `starter/main.cpp` (код с проблемой ABA — для анализа, запускать
не обязательно).

Сборка (код компилируется):

```
g++ -std=c++17 -pthread -Wall -Wextra main.cpp -o lf_stack
```

Примечание: счётчик версий упаковывается с указателем в одно машинное слово
(свободные биты указателя), чтобы атомарная структура оставалась lock-free
(см. лекцию). Это платформозависимый приём.
