# Лаба 7.2. Почини публикацию узла до его готовности — средняя
Модуль: 7. Конкурентные структуры данных без блокировок
Тип: найди и почини

## Мотивация

В lock-free структуре узел обязан быть **полностью готов до публикации**:
как только `head` укажет на него, другие потоки начнут его читать, и менять
его будет уже нельзя. Если `push()` публикует узел в `head`, а данные заполняет
после — другой поток может прочитать узел, пока продюсер его пишет. Это гонка
за данные (неопределённое поведение), которую ловит ThreadSanitizer.

## Задача

В стартовом коде lock-free стек, в котором `push()` публикует узел в `head`
**до** того, как заполнит его данные. Найди ошибку и исправь её: узел должен
быть полностью готов до публикации.

## Требования

1. Узел полностью заполняется (данные, `next`) **до** `head.store`/CAS.
2. `push()` использует CAS-цикл по `head` (как в лекции).
3. `pop()` корректен и возвращает `std::shared_ptr<T>` (или пустой, если стек
   пуст).
4. Программа: несколько потоков кладут уникальные значения, несколько потоков
   извлекают; в конце собраны все значения ровно по одному разу.
5. Код компилируется без предупреждений; TSan не находит гонку за данные.

## Стартовый код

Файлы: `starter/main.cpp`.

Сборка:

```
g++ -std=c++17 -pthread -Wall -Wextra main.cpp -o lf_stack
```

Проверка гонки (на решении должно быть чисто):

```
g++ -std=c++17 -pthread -fsanitize=thread -g main.cpp -o lf_stack_tsan
./lf_stack_tsan
```

## Чеклист самопроверки

- Нашёл, какое поле узла пишется после публикации узла в `head`.
- Узел готовится полностью до публикации.
- Все значения извлечены ровно по одному разу; TSan чист.
