# Решение лабы 7.2

## Ошибка

В `push()` узел публиковался в `head` **до** заполнения данных:

```cpp
node* new_node = new node;                   // узел с пустыми данными
new_node->next = head.load();
head.store(new_node);                        // <-- публикация
new_node->data = std::make_shared<T>(data);  // данные пишутся ПОСЛЕ
```

Как только `head.store(new_node)` выполнен, другой поток может прочитать узел
(в `pop()`). Он видит либо пустой `data` (и думает, что стек пуст), либо
полузаполненный `data`, пока продюсер его пишет. Это гонка за данные —
неопределённое поведение. ThreadSanitizer ловит её как data race на `data` узла.

## Исправление

Узел должен быть **полностью готов до публикации**. Данные задаются
в конструкторе узла, а публикация происходит CAS-циклом:

```cpp
void push(T const& data) {
    node* const new_node = new node(data);   // данные — до публикации
    new_node->next = head.load();
    while (!head.compare_exchange_weak(new_node->next, new_node)) {}
}
```

Теперь порядок такой:

1. создать узел с данными (`data` заполнен);
2. установить `next` в текущее `head`;
3. опубликовать узел через CAS (атомарно проверяя, что `head` не изменился).

После публикации узел больше не меняется — его можно только читать.

## Почему это важно

Правило «узел готов до публикации» — фундаментальное для lock-free кода.
Оно же объясняет, почему в `push()` CAS обязателен: без CAS два потока могли бы
«перезаписать» `head`, и один узел был бы потерян. CAS гарантирует, что узел
попадает в стек ровно один раз и виден другим потокам только полностью готовым.

## Проверка

С `-fsanitize=thread`:
- стартовый код ловит data race на `data` узла;
- решение — чисто, все 100000 значений извлечены ровно по одному разу.
