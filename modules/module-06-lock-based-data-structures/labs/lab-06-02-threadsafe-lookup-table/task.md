# Лаба 6.2. Потокобезопасная поисковая таблица
Модуль: 6. Конкурентные структуры данных с блокировками
Тип: допиши TODO

## Мотивация

Поисковая таблица (словарь) — структура, которую читают часто, а меняют редко
(кэши, конфигурации). Единый мьютекс сериализовал бы всех читателей.
Решение — хеш-таблица с **отдельным `std::shared_mutex` на каждый сегмент**:
много читателей работают параллельно, а запись в один сегмент не мешает
операциям над другими.

## Задача

В стартовом коде дан каркас `threadsafe_lookup_table` с готовой инфраструктурой
(сегменты, `get_bucket`, хеширование). Допиши три метода внутреннего класса
`bucket_type`: `value_for`, `add_or_update_mapping`, `remove_mapping`.

## Требования

1. `value_for(key, default_value)` — если ключ найден, возвращает связанное
   значение; иначе `default_value`. Чтение не мешает другим чтениям того же
   сегмента.
2. `add_or_update_mapping(key, value)` — если ключа нет — добавляет пару,
   если есть — обновляет значение. Добавление и обновление — одна операция.
3. `remove_mapping(key)` — удаляет запись по ключу, если она есть.
4. В изменяющих методах используй вспомогательный метод `find_entry_for`
   (уже реализован); в `value_for` (он `const`) выполни поиск аналогично
   по `const`-данным.
5. Программа: несколько потоков параллельно добавляют и читают записи;
   в конце все добавленные ключи читаются корректно.
6. Код компилируется без предупреждений; TSan не находит гонку за данные.
