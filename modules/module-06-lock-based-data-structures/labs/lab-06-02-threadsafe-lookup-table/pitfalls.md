# Грабли лабы 6.2

## Использовал `std::mutex` вместо `shared_mutex`

`std::mutex` сериализует читателей: даже чтение становится эксклюзивным.
Смысл `shared_mutex` — конкурентное чтение. Для `value_for` используй
`shared_lock`, для изменяющих методов — `unique_lock`.

## Забыл `mutable` у мьютекса

`value_for` — `const`-метод. Если `shared_mutex` не помечен `mutable`, `const`
метод не сможет его заблокировать — ошибка компиляции. Блокировка не меняет
логическое состояние, поэтому `mutable` корректен.

## Разделил «добавить» и «обновить» на две операции

Если сделать `add(key, value)` и `update(key, value)` отдельно, между проверкой
наличия и изменением может вклиниться другой поток — гонка интерфейса. Одна
функция `add_or_update_mapping` выполняет проверку и изменение под одной
блокировкой — это устраняет гонку.

## Не обработал случай «ключ не найден»

В `value_for` обязательно проверяй `found_entry == data.end()` — иначе разыменуешь
`end()` (UB). В `add_or_update_mapping` и `remove_mapping` — аналогично проверяй
результат поиска перед действием.

## Проверял только «по поведению» без TSan

Гонка за данные может не проявляться годами. Прогони `-fsanitize=thread`.
Также помни: чтение после `join()` писателей не проверяет конкурентную запись —
для полноты гоняй сценарии, где читатели и писатели работают одновременно.
