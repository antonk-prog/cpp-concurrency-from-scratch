# Решение лабы 6.4

## Ошибка

`push()` будит ровно одного ожидающего через `notify_one()`. В наивной
`wait_and_pop()` разбуженный поток безусловно сохраняет элемент:

```cpp
void wait_and_pop(T& value) {
    std::unique_lock<std::mutex> lk(mut);
    data_cond.wait(lk, [this] { return !data_queue.empty(); });
    value = std::move(data_queue.front());   // может бросить!
    data_queue.pop();
}
```

Если присваивание в `value` бросает исключение (тяжёлый/бросающий тип
элемента), функция выходит, `pop()` не выполняется, и элемент **остаётся
в очереди**. Но других уведомлений не было: остальные потоки продолжают ждать
на `data_cond`, хотя данные доступны. Программа «зависает».

## Исправление

Присваивание и удаление оборачиваются в `try`, а в `catch` добавляется
`notify_one()` — будим следующего, затем пробрасываем исключение:

```cpp
void wait_and_pop(T& value) {
    std::unique_lock<std::mutex> lk(mut);
    data_cond.wait(lk, [this] { return !data_queue.empty(); });
    try {
        value = std::move(data_queue.front());
        data_queue.pop();
    } catch (...) {
        data_cond.notify_one();
        throw;
    }
}
```

Разберём по шагам:

- **Элемент не теряется.** Бросить может только присваивание; `pop()` до него
  не доходит, значит, элемент по-прежнему в очереди. Разбуженный следующим
  поток увидит непустую очередь и заберёт его.
- **`notify_one()` до снятия блокировки.** Уведомление делается под `unique_lock`
  (до выхода из `catch`). Разбуженный поток не сможет встать на мьютекс, пока
  мы его не освободим при разворачивании стека, — это корректно и безопасно.
- **Исключение пробрасывается.** `throw;` не даёт проглотить ошибку: вызывающий
  код узнаёт о сбое, но очередь остаётся в согласованном состоянии.
- **RAII.** `unique_lock` снимет мьютекс при любом выходе, в том числе по
  исключению.

Почему это правильнее альтернатив:

- `notify_all()` тоже разбудило бы всех и «заработало», но большинство потоков
  напрасно проснётся, снова обнаружит пустую очередь (её заберёт один) и уснёт.
  `notify_one()` будит ровно столько, сколько нужно.
- Хранить в очереди `std::shared_ptr<T>` (листинг 6.3) убирает сам источник
  исключения: копирование `shared_ptr` не бросает. Тогда `wait_and_pop()`
  становится безопасной без `notify` в `catch`. Оба подхода допустимы;
  здесь закрепляется вариант с `notify_one()`.

Тот же приём применяется и к перегрузу `std::shared_ptr<T> wait_and_pop()`,
где исключение может бросить `std::make_shared<T>()` (например, нехватка
памяти): элемент ещё не удалён, поэтому `notify_one()` разбудит следующего.

## Проверка

Демонстрационная программа ставит `payload::throw_once = true` и кладёт один
элемент. Два потребителя ждут `wait_and_pop`:

- **стартовый код:** первый потребитель получает исключение, `notify` не
  делается, второй остаётся ждать — программа печатает `BUG` (код 1);
- **решение:** первый в `catch` будит второго; второй успешно забирает тот же
  элемент (`succeeded = 1, failed = 1`) — печатается `OK` (код 0).

С `-fsanitize=thread` решение чисто: все обращения к очереди идут под мьютексом,
гонки за данные нет.
