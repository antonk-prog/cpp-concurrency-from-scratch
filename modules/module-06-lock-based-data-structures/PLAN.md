# Модуль 6 — Конкурентные структуры данных с блокировками — ПЛАН

## Допущения модуля

### Прогрессия (что разрешено)
- Всё из модулей 1–5: потоки, мьютексы, условные переменные, фьючерсы,
  атомарные операции. Новых примитивов в главе 6 НЕТ — это глава о том,
  как **проектировать** потокобезопасные структуры данных на уже изученных
  примитивах.
- Ключевые примитивы для лаб: `std::mutex`/`lock_guard`/`unique_lock`
  (гл. 3), `std::condition_variable` (гл. 4), `std::shared_mutex`/`shared_lock`
  (гл. 3), умные указатели (`unique_ptr`, `shared_ptr`), `std::stack`/`std::queue`/
  `std::list`/`std::map`/`std::hash`.
- Атомарные операции (гл. 5) — в лабах НЕ использовать (структуры с блокировками
  строятся на мьютексах; lock-free — тема главы 7).
- Запрещено всё из C++20+: `std::jthread`, `std::counting_semaphore`,
  `std::barrier`, `std::latch`, корутины, `std::format`.
- Concurrency TS — не используется в этой главе вообще.

### Тематика (соответствие главе 6)
Лекция покрывает:
- 6.1 Что означает разработка структур данных для конкурентного доступа
  (потокобезопасность, сериализация, рекомендации 6.1.1).
- 6.2 Базовые структуры на блокировках:
  - 6.2.1 потокобезопасный стек (листинг 6.1);
  - 6.2.2 потокобезопасная очередь с условными переменными (листинги 6.2–6.3);
  - 6.2.3 очередь с подробной детализацией блокировок — фиктивный узел,
    head/tail мьютексы (листинги 6.4–6.10).
- 6.3 Более сложные структуры:
  - 6.3.1 потокобезопасная поисковая таблица (hash table с бакетами
    на `shared_mutex`) (листинги 6.11–6.12);
  - 6.3.2 потокобезопасный список с эстафетной блокировкой по узлам
    (листинг 6.13).

### Список лаб (тип, название, суть, чему учит)

1. **lab-06-01-fine-grained-queue (найди и почини, средняя)**
   - Суть: дана очередь с детализацией блокировок (head/tail мьютексы),
     но `get_tail()` вызывается ВНЕ блокировки `head_mutex` — та самая ошибка
     из книги: head может «перескочить» за tail и разрушить структуру.
     Найти баг, понять, почему он разрушает инварианты, и починить.
   - Чему учит: тонкости детализации блокировок, инварианты структуры,
     порядок захвата мьютексов в `pop_head`.
   - Прогрессия: mutex + unique_ptr, никаких новых примитивов.

2. **lab-06-02-threadsafe-lookup-table (допиши TODO, сложная)**
   - Суть: дан каркас потокобезопасной поисковой таблицы (hash table
     с бакетами, каждый на `std::shared_mutex`). Дописать методы бакета:
     `value_for`, `add_or_update_mapping`, `remove_mapping`.
   - Чему учит: проектирование потокобезопасного интерфейса, `shared_mutex`
     (чтение-запись), инварианты структуры.
   - Прогрессия: shared_mutex (гл. 3) + std::list/std::hash.

3. **lab-06-03-threadsafe-list (напиши с нуля, сложная)**
   - Суть: реализовать потокобезопасный односвязный список с мьютексом
     на каждом узле и эстафетной блокировкой (for_each, find_first_if,
     remove_if) по мотивам листинга 6.13.
   - Чему учит: эстафетная (hand-over-hand) блокировка, итерация без
     итераторов STL, безопасность при удалении узлов.
   - Прогрессия: mutex + unique_ptr + шаблоны.

## Заголовки лекции (README.md) с 1–2 фразами содержания

1. **Зачем это нужно** — после низкоуровневых атомарных (гл. 5) возвращаемся
   к структурам данных; почему нужны именно потокобезопасные контейнеры,
   а не «мьютекс вокруг std::map».

2. **Что такое потокобезопасная структура данных (6.1)** — потокобезопасность,
   сериализация, два аспекта: безопасность и конкурентность.

3. **Рекомендации (6.1.1)** — четыре правила (инварианты, интерфейс без гонок,
   исключения, минимизация deadlock) + вопросы о детализации.

4. **Потокобезопасный стек (6.2.1)** — листинг 6.1, разбор инвариантов
   и исключений, ограничения (сериализация, нет ожидания).

5. **Потокобезопасная очередь с условными переменными (6.2.2)** — листинги
   6.2–6.3: wait_and_pop/try_pop, безопасность исключений в wait_and_pop
   (не забыть про остальных ожидающих при исключении).

6. **Детализация блокировок: очередь на односвязном списке (6.2.3)** —
   фиктивный узел, разделение head/tail, листинги 6.4–6.10: почему фиктивный
   узел, инварианты, get_tail под head_mutex, добавление ожидания.

7. **Потокобезопасная поисковая таблица (6.3.1)** — hash table с бакетами,
   shared_mutex на бакет, листинги 6.11–6.12, get_map с блокировкой всех
   бакетов.

8. **Потокобезопасный список с эстафетной блокировкой (6.3.2)** — листинг
   6.13: мьютекс на узел, for_each/find_first_if/remove_if, почему нет
   итераторов STL.

9. **Типичные ошибки** — единый мьютекс вместо детализации, возврат ссылки
   из структуры, гонка empty/top/pop, удаление узла под чужим мьютексом,
   инверсия порядка блокировок.

10. **Шпаргалка** — таблица: структура, примитив, инварианты, что даёт.

## Дополнительно

- **Акценты лектора (A013):** подчеркнуть, что потокобезопасность ≠ просто
