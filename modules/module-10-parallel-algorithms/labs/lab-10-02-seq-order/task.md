# Лаба 10.2. Порядок операций с seq — средняя
Модуль: 10. Алгоритмы параллельных вычислений
Тип: предскажи вывод

## Мотивация

Политика выполнения меняет не только возможность распараллеливания. Даже
`std::execution::seq`, выполняющий всё в одном потоке, отменяет гарантию
порядка: обычный `std::for_each` обрабатывает элементы строго по порядку, а
`for_each(seq)` — «как угодно, лишь бы без перемежения». На такой код легко
положиться «на практике» — и ошибиться.

## Задача

Дан фрагмент:

```cpp
std::vector<int> v(1000);
int count = 0;
std::for_each(std::execution::seq, v.begin(), v.end(),
              [&](int& x) { x = ++count; });
```

1. **Предскажи, гарантировано ли, что в `v` окажется последовательность
   1, 2, …, 1000.** Обоснуй ответ: что обещает политика `seq` и чем она
   отличается от `std::for_each` без политики.
2. Запусти программу и проверь предсказание: на конкретной машине результат
   может выглядеть «правильным» — объясни, почему на это всё равно нельзя
   полагаться.
3. В `solution/` сравни поведение `for_each(seq)` и `for_each` без политики.

## Требования

1. Предсказание записано ДО запуска: «гарантировано / не гарантировано» +
   объяснение.
2. Объяснено, чем `seq` отличается от вызова без политики (порядок операций).
3. Программа печатает результат проверки и завершается успешно (exit 0).

## Стартовый код

Файлы: `starter/main.cpp`.

Сборка и запуск:

```
g++ -std=c++17 -pthread -Wall -Wextra main.cpp -o seq_order
./seq_order
```

## Чеклист самопроверки

- Предсказание сделано и проверено запуском.
- Отличие `seq` от обычного алгоритма объяснено.
- Вывод программы понятен (результат проверки напечатан).
