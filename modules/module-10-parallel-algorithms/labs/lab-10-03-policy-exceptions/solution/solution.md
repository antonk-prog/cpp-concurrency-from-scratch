# Решение лабы 10.3

## Предсказание

**Режим без политики** — `std::for_each` выполняет лямбду в потоке
вызывающего; исключение `my_exception` распространяется по стеку и
перехватывается `catch (my_exception const&)`. Программа напечатает:

```
mode: без политики
CAUGHT
```

**Режим `--policy`** — `std::for_each(std::execution::seq, ...)` с политикой.
При неперехваченном исключении из пользовательского кода стандартная политика
вызывает `std::terminate`: исключение НЕ распространяется к `catch`, процесс
аварийно завершается. На практике программа упадёт с сообщением
`terminate called after throwing an instance of 'my_exception'` — «CAUGHT»
напечатано не будет.

## Почему terminate

Параллельные алгоритмы могут выполнять операции в других потоках или с
перемежением. Распространять исключение «по стеку» в такой схеме нельзя:
стек не тот, а операция может идти в другом потоке. Поэтому стандарт выбирает
жёсткое поведение: любое неперехваченное исключение из пользовательского кода
приводит к `std::terminate`. Это касается всех трёх политик — в том числе `seq`,
хотя она и не параллелит.

Единственное исключение, которое вызов алгоритма с политикой может выбросить
сам, — `std::bad_alloc`: если библиотеке не хватило памяти на внутренние
структуры. Пользовательские исключения «наружу» не выходят.

## Практический вывод

Если внутри операции возможны исключения, которые нужно перехватить, —
не используй политики: либо обычный алгоритм без политики, либо перехватывай
исключение внутри самой лямбды (не давая ему выйти за пределы операции).
Второй способ совместим с политиками: исключение «проглатывается» внутри
операции, наружу не распространяется.

## Проверка

Режим по умолчанию печатает `CAUGHT`, exit 0. Режим `--policy` завершается
аварийно (terminate) — это и есть ожидаемое поведение, часть ответа.
