Тип: допиши TODO

## Мотивация

Конвейер «производитель-потребитель» — одна из самых распространённых схем
многопоточного кода: один поток готовит порции данных, другой их обрабатывает.
Потребитель не должен крутить пустой цикл опроса — он должен по-настоящему
заснуть и проснуться, когда данные появились. Именно это даёт условная
переменная `std::condition_variable` в паре с `std::unique_lock`.

## Задача

В стартовом коде есть класс `threadsafe_queue` (очередь + мьютекс +
`std::condition_variable`) с недописанными методами и `main` с продюсером
и консьюмером. Допиши недостающие части (отмечены `TODO`):

1. `push(T value)` — положить значение в очередь под `lock_guard` и
   уведомить один ожидающий поток через `data_cond.notify_one()`.
2. `wait_and_pop(T& value)` — под `unique_lock` вызвать
   `data_cond.wait(lk, [this] { return !data_queue.empty(); })`, затем извлечь
   элемент из очереди в `value`.
3. `try_pop(T& value)` — под `lock_guard` проверить, не пуста ли очередь;
   если пуста — вернуть `false`, иначе извлечь элемент в `value` и вернуть `true`.

Логику продюсера и консьюмера в `main` не меняй: продюсер кладёт числа от 1 до
`N`, консьюмер извлекает их через `wait_and_pop()` и суммирует. Программа должна
печатать сумму и завершаться корректно.

Ожидаемый вывод (сумма чисел 1..100):

```
Sum = 5050
```

## Требования

1. Сборка без ошибок и предупреждений:
   `g++ -std=c++17 -pthread -Wall -Wextra main.cpp -o /tmp/lab_04_01`.
2. `push` использует `lock_guard` и вызывает `notify_one()` после записи.
3. `wait_and_pop` использует `unique_lock` и `wait` с предикатом
   `!data_queue.empty()`.
4. `try_pop` возвращает `false` на пустой очереди, не бросая исключений.
5. Программа выводит `Sum = 5050` и завершается кодом 0.

```

/tmp/lab_04_01
```
