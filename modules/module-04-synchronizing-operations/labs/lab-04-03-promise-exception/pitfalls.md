# Грабли 4.3

## Сигнал до данных

`set_value()` до заполнения буфера — data race: потребитель может проснуться по
`get()` и читать буфер, пока поставщик ещё пишет. Записывай данные ДО
`set_value()`, чтобы синхронизация promise→future гарантировала видимость.

## Пустой `catch` → broken_promise

Если в `catch` ничего не установить, а `set_value()` не успел выполниться,
промис уничтожается без результата — ожидающий получает `broken_promise`.
Всегда устанавливай значение или исключение (`set_value`/`set_exception`).

## Считаешь, что `set_value`/`get` упорядочивает всё

`set_value()` синхронизируется с `get()` только для записей, сделанных ДО
`set_value()`. Записи ПОСЛЕ `set_value()` не покрываются — они остаются гонкой.

## Забыл `std::current_exception()`

Чтобы передать исключение во фьючерс, его нужно захватить: либо через
`std::current_exception()` в `catch`, либо создать напрямую —
`std::make_exception_ptr(std::runtime_error("..."))`.

## Дважды вызываешь `get()`

`std::future::get()` можно вызвать один раз. Если результат нужен нескольким
потокам — `shared_future` или копии.
