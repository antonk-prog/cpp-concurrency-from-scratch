# Лаба 4.3. Почини сигнал готовности
Модуль: 4. Синхронизация конкурентных операций
Тип: найди и почини

## Мотивация

`std::promise`/`std::future` — это не только способ передать значение, но и
механизм **синхронизации**: вызов `promise.set_value()` устанавливает
отношение «произошло до» с вызовом `future.get()` в другом потоке. Значит,
всё, что записано ДО `set_value()`, гарантированно видно после `get()`. Но если
нарушить порядок (писать после `set_value` или не устанавливать promise вообще),
получаются либо гонка за данные, либо `broken_promise`.

## Задача

Дан стартовый код: поток-поставщик готовит данные в общий буфер `buffer`
и сообщает об этом через `std::promise<void> ready`; поток-потребитель ждёт
`ready.get_future().get()` и затем проверяет данные. В коде **два** заложенных
дефекта:

1. **Гонка за буфер.** `ready.set_value()` вызывается **до** заполнения `buffer`.
   Потребитель просыпается по `get()` и начинает читать `buffer`, пока
   поставщик ещё пишет — это data race / UB. TSan ловит.
2. **Потерянный сигнал при исключении.** В блоке `catch` promise не
   устанавливается, а `set_value()` мог не успеть выполниться — при уничтожении
   неинициализированного promise ожидающий получает исключение
   `std::future_error` с кодом `broken_promise`.

Найди и исправь оба дефекта так, чтобы:

- `buffer` заполнялся **до** `ready.set_value()` (тогда `set_value` → `get`
  гарантирует видимость данных);
- promise всегда получал значение **или** исключение (`set_value` / `set_exception`),
  даже если подготовка данных бросает исключение.

Логику `compute_data` (заполнение буфера) и проверки потребителя не меняй.

Программа должна печатать `OK` и завершаться кодом 0.

## Требования

1. Сборка без ошибок и предупреждений:
   `g++ -std=c++17 -pthread -Wall -Wextra main.cpp -o /tmp/lab_04_03`.
2. `set_value()` вызывается строго после завершения записи в `buffer`.
3. На всех путях (включая исключение из `compute_data`) promise устанавливается:
   либо значением, либо исключением — без `broken_promise`.
4. Программа печатает `OK` и завершается кодом 0.
5. TSan на исправленном коде не находит гонок.

## Стартовый код

Один файл `main.cpp` с обоими дефектами. Собери, запусти, затем проверь под
TSan (гонка видна только там):

```
g++ -std=c++17 -pthread -Wall -Wextra main.cpp -o /tmp/lab_04_03
/tmp/lab_04_03

g++ -std=c++17 -pthread -fsanitize=thread -g main.cpp -o /tmp/lab_04_03_tsan
/tmp/lab_04_03_tsan
```
